# v2.9.4 — mcp-tools-list-schema-shim

## Summary

Wires static schema classification into the MCP runner and executor pipelines
so that declared write or read tools are correctly classified even when their
names lack the expected keywords. Adds `tools_list()` and `classify_all()`
helpers to `MCPSchemaStore`. Schema metadata remains optional and experimental;
schema-absent workloads are unchanged.

## Changed Files

- `src/safecode/mcp/schema.py` — adds `MCPSchemaStore.tools_list()` and `classify_all()`
- `src/safecode/mcp/runner.py` — `MCPReadOnlyRunner` accepts optional `schemas` list;
  `call_readonly` and `propose_write` use `classify_with_schema` instead of keyword-only classification
- `src/safecode/mcp/loop_executor.py` — `MCPReadToolExecutor` accepts optional `schemas` list;
  `execute` uses `classify_with_schema` for the read-only gate check
- `tests/test_mcp_tools_list_schema_shim.py` — 24 new tests
- `pyproject.toml`, `src/safecode/__init__.py` — version bumped to 2.9.4
- `.claude/versions.json`, `.claude/skills/current/SKILL.md` — baseline updated
- `docs/version_implementation_matrix.md` — v2.9.4 row added

## Constraints Preserved

- No real JSON-RPC client. Classification is pure static metadata + keyword matching.
- Schema-less workloads (`schemas=[]` or `schemas=None`) behave identically to v2.9.3.
- `classify_with_schema` falls back to `classify_mcp_tool` when no schema matches.
- No approval, audit, sandbox, or policy gates weakened.
