# v4.6.0 - memory facade and CLI

## Status

Implemented. All v4.6 memory surfaces are EXPERIMENTAL. No stable public contracts were promoted.

## What changed

- Added `MemoryFacade(project_root)` in `src/safecode/memory/facade.py`.
- New writes use `.sac/memory/project.md`, `.sac/memory/recent-failures.jsonl`, `.sac/memory/recent-edits.jsonl`, `.sac/memory/pinned-files.txt`, and `.sac/tasks/<task_id>/memory.md`.
- Legacy `.sac/memory.json`, `.sac/progress.md`, and `SAC.md` remain readable through the unified project-memory view.
- Recent failures and recent edits are capped to the newest 200 entries.
- Memory reads shown by CLI are redacted, and obvious secret-like writes are rejected.
- Pinned files are normalized relative to the project root, stored sorted and unique, and paths outside the project root are refused.
- Replaced the old hidden `sac memory <key> <value>` shim with experimental `sac memory show`, `pin`, `unpin`, `add-note`, and `clear`.
- `sac memory clear` requires confirmation or `--yes`.
- JSON output uses the existing `CLIJSONResponse` envelope.

## Safety notes

- New writes do not update legacy `.sac/memory.json`.
- Missing pinned files are allowed for now and will be surfaced by context selection in v4.6.1.
- No `PatchProposal` or `AuditEvent` field sets changed.
- No stable contract promotion was made.
