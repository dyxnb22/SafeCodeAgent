# v2.4.0 — Docker Sandbox Backend Preview

## Summary

First real sandbox backend execution beyond the Noop adapter. Docker
containers are now supported when a Docker daemon is reachable. macOS
Seatbelt and Linux Bubblewrap remain plan-only.

## What Changed

### New: `DockerExecutor` (`src/safecode/sandbox/docker.py`)
- Reconstructs the docker run argv from the stored `SandboxExecutionProposal`
  fields and verifies the `preview_hash` before execution.
- Checks daemon availability via `DockerDaemonChecker` (`docker info`).
- Executes `subprocess.run(argv, capture_output=True, shell=False)` — no
  `shell=True`, no string interpolation.
- Returns `DockerExecutionResult` (frozen dataclass: `executed`, `exit_code`,
  `stdout`, `stderr`, `duration_ms`, `message`).
- Injectable `daemon_checker` and `run_fn` make the class fully testable
  without a real Docker daemon.

### New: `DockerDaemonChecker` (`src/safecode/sandbox/docker.py`)
- Checks daemon reachability with a 5-second timeout via `docker info`.
- Returns `(available: bool, reason: str)`. Never raises.

### Updated: `DockerSandboxAdapter.supports_execution()` (`sandbox/adapter.py`)
- Now returns `True` (was `False` in v1.7.x–v2.3.x).
- `build_plan()` warnings updated to reflect v2.4.0 preview status.

### Updated: `SandboxExecutionGate.execute_pending()` (`sandbox/execution.py`)
- Adds a Docker branch after the atomic approval claim.
- Delegates to `DockerExecutor.execute(proposal)`.
- Writes `sandbox_execution_completed` audit event when Docker ran (even
  non-zero exit); writes `sandbox_execution_blocked` when Docker was
  unreachable or hash-mismatched.
- Writes a result record and clears the pending proposal for all paths,
  matching Noop lifecycle semantics.

### Updated: `SandboxExecutionPreflight` (`sandbox/preflight.py`)
- Error message for `backend_supports_execution=False` updated to name
  macOS Seatbelt and Linux Bubblewrap as still plan-only.

### Updated: `cli_sandbox.py`
- `sac sandbox status` scope panel updated to v2.4.0.
- Docker row in capability table shows "executing (preview)".
- `sac sandbox plan` trailing note distinguishes Docker (propose → execute
  flow) from macOS/Linux (still plan-only).
