# v2.7.0 audit-consolidation-baseline

Consolidates audit findings from product-audit-v2.6.21 into the main branch.

## Changes

- **Policy presets now apply on load**: `SafeCodeConfig.load()` applies the selected policy preset
  when `policy` is explicitly set in user config, project config, or `SAFECODE_POLICY` env var.
  Manual shell config without an explicit policy selection is preserved.
  Trusted two-sided network opt-in (both user and project must enable) survives preset application.
- **`sac doctor` default is environment-only**: Release diagnostics
  (`release_version`, `release_tag`, `release_docs`, `release_preflight`) are now opt-in via
  `sac doctor --release`. Default `sac doctor` only shows environment checks.
- **Non-zero exit on blocked/approval-required**: `sac run` and `sac test run` propagate non-zero
  exit codes when a command is blocked or requires approval.
- **Sandbox Noop wording corrected**: `sac sandbox status` and `sac sandbox plan` now accurately
  describe the Noop backend as `policy-gated (no OS containment)` instead of claiming execution.
- **Hook approval policy version is schema-scoped**: `APPROVAL_POLICY_VERSION` is now the stable
  string `"hook-approval-v1"` rather than `f"{SAFECODE_VERSION}-hook-approval-v1"`, so approvals
  do not silently expire on every patch release.
- **Release bump no longer modifies test files**: `bump_versions()` only updates `pyproject.toml`
  and `src/safecode/__init__.py`. Tests validate version shape dynamically instead of carrying
  patch-release literals.
- **`sac release changelog --recent N`**: New `--recent N` flag generates a changelog for the
  latest N version notes. CI uses `--recent 5`.
- **versions.json and SKILL.md baseline corrected to v2.6.21**.

## Acceptance

- `PYTHONPATH=src python3 -m pytest -q` — 1871 tests pass.
- `sac doctor` default output does not contain release_version/release_tag/release_docs/release_preflight.
- `sac doctor --release` output contains all four release diagnostics.
- `sac sandbox status` shows "no OS containment" for Noop backend.
