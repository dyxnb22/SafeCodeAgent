# v3.7.2 — repo recency signal + JSON envelope promotion

## Summary

- **T-3.7.2-A repo-recency-signal** (`src/safecode/context/selector.py`): `ContextSelector`
  now weights recently git-touched files higher using a `_RECENCY_BONUS = 2` additive multiplier
  on top of existing keyword-match scoring. Recency is determined by `git log -n50 --name-only`
  and cached keyed to `git rev-parse HEAD` (invalidated on new commits). Git failures (no repo,
  timeout, OSError) fall back silently — no recency bonus, existing behavior unchanged.
  22 new tests in `tests/test_context_recency.py`.

- **T-3.7.2-B json-envelope-promote** (`docs/public-contracts.md`,
  `tests/snapshots/contracts/cli_json_envelope.json`,
  `tests/test_public_contract_snapshots.py`): `CLIJSONResponse` promoted to stable contract
  (Section 11 in `docs/public-contracts.md`). Snapshot enforces field set (`command`, `status`,
  `data` required; `error` optional/omitted-when-null). 12 new tests in
  `TestCLIJSONEnvelopeContract`; `TestCrossContractDeterminism` parametrize list extended.

## Safety invariants preserved

- Recency is purely additive; a file with no keyword match is never included.
- Git subprocess uses `shell=False` with a 10-second timeout.
- JSON envelope shape is unchanged from v3.1.0; this is a promotion, not a modification.
