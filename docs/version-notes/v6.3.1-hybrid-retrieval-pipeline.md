# v6.3.1 — hybrid-retrieval-pipeline

## Summary

Adds a hybrid context retrieval pipeline combining keyword, semantic, and
git-recency signals. Every result carries a `selection_reason` field.

## What changed

### New module: `src/safecode/context/hybrid_retrieval.py`

- `HybridResult` dataclass: `path`, `keyword_score`, `semantic_score`,
  `combined_score`, `selection_reason`.
- `HybridRetriever.retrieve(query, limit, semantic_weight)`:
  1. Gets keyword sources from `ContextSelector.select_sources()`.
  2. Gets semantic scores from `EmbeddingStore.search()` (empty if no index/null backend).
  3. Merges and re-ranks by `combined_score = (1 - w) * kw + w * sem`.
  4. `selection_reason` explains which signals fired ("path matched: auth; semantic (0.81)").

### New CLI command: `sac search "<query>"`

Registered as a visible top-level command in `src/safecode/cli.py`.
Outputs a ranked table with combined score, path, and selection reason.
`--json` returns `{"query": ..., "results": [...]}`.

## Invariants

- `HybridRetriever` never raises; semantic failure silently returns keyword-only results.
- `selection_reason` is always a non-empty string.
- Results are bounded by the `limit` argument.
- Existing `ContextSelector.select()` / `select_sources()` are unchanged.
