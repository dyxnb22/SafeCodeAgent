# v3.8.2 — MCP write-proposal e2e + MCP read promotion

## Summary

- **T-3.8.2-A mcp-write-proposal-e2e**: Wired approval-gated MCP write flow end-to-end against a stub JSON-RPC server. Added `MCPApprovalStore` in `src/safecode/mcp/approval_grant.py` — stores single-use approval grants outside the project root (`SAFECODE_MCP_APPROVAL_DIR` env var; default `~/.sac/mcp/approvals/`). Added `execute_granted_write(proposal_id, server, tool, ...)` to `MCPReadOnlyRunner` — consumes the approval grant (single-use), routes through stdio transport, emits `mcp_granted_write_started`/`mcp_granted_write_completed`/`mcp_granted_write_blocked` audit events, and discards the pending proposal after execution. Requires `stdio_runner=True` (or `SAFECODE_MCP_STDIO_RUNNER=1`) and server `argv`. 19 new tests in `tests/test_mcp_write_proposal_e2e.py`.

- **T-3.8.2-B mcp-read-promotion**: Added "MCP Read Execution Contract" (Section 12) to `docs/public-contracts.md`. Created `tests/snapshots/contracts/mcp_read_contract.json` with result fields, gate order, scope vocabulary, and invariants. Extended `tests/test_public_contract_snapshots.py` with `TestMCPReadContract` (16 tests). Dropped "experimental" label from MCP read execution; MCP write execution and lifecycle remain experimental and are explicitly listed in the Experimental Surfaces table.

## Key invariants

- Approval grants stored outside project root (`SAFECODE_MCP_APPROVAL_DIR`); project cannot forge approvals.
- Single-use: `MCPApprovalStore.consume()` deletes the grant file after reading.
- `execute_granted_write` requires `SAFECODE_MCP_STDIO_RUNNER=1` and server `argv`.
- Pending proposal discarded after successful execution.
- Scope gate still runs BEFORE classification (v3.8.1 invariant preserved).
- MCP write execution and lifecycle remain experimental; only read execution promoted.
- No safety gate weakened; default LLM provider remains `mock`; no real network in tests.
