# v4.21.0: edit-and-write-tools

## Base
- Depends on: `v4.20.2`

## Completion Notes
- `src/safecode/agent/write_tools.py` (new): `edit_file` and `write_file` native tools.
  - Both have `requires_approval=True` and `audit_event_type="tool_call_write"`.
  - When `_approved=False`, return a `blocked` result with `diff_preview` in metadata.
  - When `_approved=True`, create a `CheckpointMetadata` via `CheckpointManager` before
    applying via `PatchApplier`; checkpoint_id included in result metadata.
  - `edit_file`: validates old_string uniqueness (error on 0 matches or >1 matches).
  - `write_file`: blocks `.sac/`, `.git/`, and other SKIP_DIRS; creates new or overwrites.
  - `register_write_tools(dispatcher, project_root, *, approved)` wires both tools.
- **Bug B6 fix** (`patch/applier.py`): `_prepare_operations` and `apply()` now support
  `create` (new file, `content` field) and `delete` (remove file, checkpoint holds backup).
  Unknown operation types raise `PatchValidationError`.
- **Bug B7 fix** (`patch/applier.py`): `PatchApplyError(PatchValidationError)` class added.
  `PermissionError`/`OSError` during read-before-update, atomic-write, create, and delete
  are caught and re-raised as `PatchApplyError` (extends `PatchValidationError` for
  backward compatibility). Rollback still runs before re-raise.
- **Bug B8 fix** (`agent/loop.py`): `AgentLoop.run()` default `max_steps` raised from 5 to 20.
- No stable contract promoted; no safety gate weakened.
