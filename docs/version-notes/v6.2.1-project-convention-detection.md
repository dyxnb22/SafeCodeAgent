# v6.2.1 — project-convention-detection

## Summary

Adds project convention facts: the agent proposes inferred conventions after
each session, and users approve them before they are injected into context.

## What changed

### New module: `src/safecode/memory/facts.py`

- `ProjectFact` dataclass: `fact_id` (sha256 prefix), `key`, `value`,
  `source` (auto/user), `status` (pending/approved/rejected), `created_at`,
  `approved_at`.
- `ProjectFactStore`: JSON store at `.sac/memory/facts.json`, capped at 200.
  - `propose(key, value, source)` — rejects duplicates and sensitive values.
  - `approve(fact_id)` — marks pending → approved; raises if not pending.
  - `reject(fact_id)` — marks pending → rejected.
  - `list_facts(status=None)` — filtered list.
  - `approved_context(max_chars)` — compact block for context injection.
  - `propose_from_session_summary(commands_run, touched_files)` — auto-detect
    test/lint/typecheck/build commands and guarded directories.

### AgentLoop wiring (`src/safecode/agent/loop.py`)

- `_prepend_session_memory()` now also includes approved facts via
  `ProjectFactStore.approved_context()`.
- `_write_session_summary()` calls `ProjectFactStore.propose_from_session_summary()`
  after writing the session summary — always fail-closed.

### New CLI commands (`src/safecode/cli_memory.py`)

- `sac memory list-facts [--pending|--approved] [--json]`
- `sac memory approve-fact <fact-id> [--json]` — writes `memory_fact_approved`
  audit event.
- `sac memory reject-fact <fact-id> [--json]`

### Tests

- `tests/test_memory_facts.py` — 47 tests covering `ProjectFact` round-trip,
  `ProjectFactStore` CRUD/filtering/persistence/corruption-safety, helper
  functions (`_classify_command`, `_detect_guarded_dirs`, `_looks_sensitive`),
  auto-detection from sessions, and `AgentLoop` integration.

## Invariants preserved

- Facts require explicit CLI approval; project-local files cannot approve.
- Sensitive values (containing "token", "secret", "password" etc.) are
  rejected at propose time.
- Approved fact injection never bypasses policy, audit, or approval gates.
- Fact approval is audit-logged with `type="memory_fact_approved"`.
- All failures in fact proposal/injection are silently swallowed.
