# v2.8.9 Audit and Hook Event Dedup

## Summary

Eliminates duplicate `hook_approval_required` audit events that were emitted when
hooks were skipped by policy.

**Root cause:** When `allow_medium_after_apply=False`, the runner already logged
`hook_skipped_by_policy`, but then also called `ShellRunner.run(approved=False)`
which returned exit code 125 (approval required), causing a second
`hook_approval_required` event to be written for the same command.

**Fix:** The hook runner now tracks `skipped_by_policy` and skips both
`hook_approval_required` and `hook_completed` for commands that were already
fully accounted for by `hook_skipped_by_policy`.

`hook_skipped_by_policy` is formally documented as a distinct additive event type.
Old audit logs (without `hook_skipped_by_policy`) continue to verify correctly via
the existing hash-chain mechanism — no migration required.

## Event type table (after v2.8.9)

| Scenario | Events emitted |
|---|---|
| Hooks disabled by policy | `hook_proposed`, `hook_skipped_by_policy` |
| Hooks allowed, approval missing | `hook_proposed`, `hook_approval_required` |
| Hooks allowed, approved, runs OK | `hook_proposed`, `hook_approval_used`, `hook_completed` |
| Hooks allowed, approved, runs and fails | `hook_proposed`, `hook_approval_used`, `hook_completed` |
