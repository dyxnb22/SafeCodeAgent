# v2.5.0 — Task Eval Fixture Format

**Stage:** v2.5.x Reliability and Evaluation
**Branch:** `v2.5.0-task-eval-format`
**Key files:** `src/safecode/eval/fixtures.py`, `src/safecode/eval/loader.py`

## Summary

v2.5.0 introduces the task eval fixture format — the first layer of the reliability and evaluation
infrastructure. A `TaskEvalFixture` is a structured, replayable description of an agent task: the
repository state to start from, the user's goal, the expected outcome, and the safety boundaries
that must be upheld throughout execution.

Fixtures are authored as JSON files and validated through Pydantic models. No replay runner is
included in this version; that belongs to v2.5.1.

71 new tests in `tests/test_task_eval_fixtures.py`.

## Domain Model (`src/safecode/eval/fixtures.py`)

### `RepoFixture`
Describes the repository environment for the eval.
- `kind="local"`: points to an existing directory on disk (requires `path`).
- `kind="inline"`: embeds file content directly via `files: dict[str, str]` so the test runner
  can materialise the repo without external dependencies (must not set `path`).
- `setup_commands: list[str]`: commands to run before the agent starts.

### `ExpectedOutcome`
What the agent is expected to produce.
- `kind`: `"patch"`, `"command"`, or `"any"`.
- `expected_exit_code`: optional expected process exit code.
- `expected_output_contains`, `expected_diff_contains`, `expected_files_changed`: evaluated by
  the replay runner (v2.5.1).

### `SafetyExpectations`
Safety behaviors the agent must uphold.
- Boolean flags (`expect_diff_review`, `expect_checkpoint`, `expect_approval_gate`) default to
  `True` — the conservative, safe value.
- `allow_network` defaults to `False`.
- `forbidden_commands`, `forbidden_file_writes`, `expect_audit_events`: checked by the replay
  runner to confirm the agent did not violate containment.

### `TaskEvalFixture`
Top-level fixture. Required: `name`, `goal`, `repo`, `expected`, `safety`.
Optional: `description`, `tags`, `timeout_seconds` (1–3600, default 120), `validation_commands`,
`expected_changed_files`, `forbidden_changed_files`.

`schema_version` is validated against `SUPPORTED_FIXTURE_SCHEMA_VERSIONS = frozenset({1})`.
Stable round-trip: `TaskEvalFixture.model_validate_json(fixture.model_dump_json())`.

## Loader (`src/safecode/eval/loader.py`)

`FixtureLoadError(ValueError)` — raised for all load/validation failures. Subclasses `ValueError`
for consistency with the project error hierarchy.

- `load_fixture(path)` — checks existence, suffix (`.json` only), reads text, parses JSON,
  validates it is a dict, then validates the Pydantic model.
- `load_fixture_from_dict(data)` — validates dict, constructs fixture. Useful in tests and for
  programmatic fixture construction without touching disk.
- `load_fixtures_from_dir(directory)` — globs `*.json`, collects all errors into one
  `FixtureLoadError` raised after scanning all files, returns list sorted by fixture name.

JSON is the canonical on-disk format — no new dependencies required.
