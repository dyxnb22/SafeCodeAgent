# v2.9.1 — agent-loop-error-recovery

## Summary

Added one bounded retry for transient structured-response failures in the agent
loop. Only contract-shaped failures explicitly marked recoverable trigger a retry.
Policy blocks, validation failures, approval-required states, and user-stop states
are never retried.

## Mechanism

1. `AgentLoop.step()` calls `choose_tool()`. If the response is a
   `RecoverableContractFailure`, the loop journals a `loop_retry` event (with
   `retry_attempt=1`) and calls `choose_tool()` once more.
2. If the retry also returns `RecoverableContractFailure`, the loop records a
   permanent failure via `record_failure()` and returns without further retrying.
3. `LLMContractViolation` (hard failure, fail-closed) is never retried.
4. `AgentStopForUserResponse` is never retried.

## New types and events

- `RecoverableContractFailure(frozen dataclass)` in `src/safecode/agent/schemas.py`:
  `step`, `method`, `message`. Importable by both `agent/loop.py` and
  `eval/loop_runner.py` without circular imports.
- `JournalEventType` gains `"loop_retry"`.
- `AgentJournalStore.record_loop_retry(session_id, step, message, retry_details)`
  appends a structured `loop_retry` event.

## Scripted client support

`ScriptedLLMClient` (from v2.9.0) now fully uses `first_fail_recoverable`:
- First `choose_tool()` call → `RecoverableContractFailure` (step index not advanced).
- Second call (retry) → real `tool_choice` from the step; step index advanced.

## Files changed

- `src/safecode/agent/schemas.py` — `RecoverableContractFailure` dataclass
- `src/safecode/agent/loop.py` — bounded retry in `step()`
- `src/safecode/state/journal.py` — `"loop_retry"` event type + `record_loop_retry()`
- `tests/test_agent_loop_error_recovery.py` — 18 new tests

## Acceptance

- First-fail second-pass fixture passes (`test_first_fail_second_pass_fixture_passes`).
- Journal records `loop_retry` event with reason details.
- Retry count bounded to one: second `RecoverableContractFailure` is permanent failure.
- Old journals without `"loop_retry"` still parse correctly.
