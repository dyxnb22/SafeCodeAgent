# v3.6.1 — Doctor Update Check

## Summary

**T-3.6.1-A `doctor-update-check`**: Doctor now reports the latest known version tag by
querying PyPI via HTTPS with no telemetry. Network failures skip the check silently
(SKIP, not FAIL). When a newer version is available, the diagnostic emits a WARN.
Up-to-date installs emit PASS.

## New files

- `tests/test_doctor_update_check.py` — 26 tests with mocked network only; no real HTTPS calls

## Modified files

- `src/safecode/doctor.py` — `_fetch_latest_pypi_version`, `_ver_tuple`, `Doctor.__init__` gains optional `fetch_latest_version` kwarg, `Doctor._update_check_diagnostic`, `run_diagnostics` calls update check

## Invariants

- `_fetch_latest_pypi_version` never raises; all error paths return `None`.
- `Doctor._update_check_diagnostic` returns SKIP on `None` fetch result (offline, 404, timeout).
- WARN when fetched version tuple > current; PASS when equal or older.
- Sends no telemetry, no identifying headers, no user-agent customization.
- `Doctor.__init__` accepts an injectable `fetch_latest_version` callable for deterministic testing.
- All tests use the injected callable; no test makes a real network call.
