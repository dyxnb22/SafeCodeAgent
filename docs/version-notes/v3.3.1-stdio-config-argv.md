# v3.3.1 — MCP stdio Server Config Argv Validation (experimental)

## Summary

Adds typed MCP stdio server config and argv validation.  No subprocess execution is
performed; `call_stdio` is not invoked.  Existing MCP runner and static schema behavior
are unchanged.

## New public symbols (experimental)

### `safecode.mcp.config.StdioArgvError`

`ValueError` subclass raised by argv validation and resolution helpers on any
failure.  Error text never includes caller-supplied params, secrets, or the
raw argv content.

### `safecode.mcp.config.validate_stdio_argv(raw) -> tuple[str, ...]`

Validates a raw argv value from config.  Accepts only a non-empty `list[str]`.

Rejects:
- Shell strings (a plain `str` value) — error includes "shell string"
- Non-list types (int, None, dict, …) — error includes "list"
- Empty list — error includes "non-empty"
- List with non-string items — error includes "not a string" and the index

Never includes the raw value content in the error message.

### `safecode.mcp.config.resolve_stdio_argv(servers, server_name) -> list[str]`

Looks up a named server and returns its validated argv as `list[str]`.

Fails closed (raises `StdioArgvError`) on:
- Missing server
- Server with no stdio argv configured (`argv=None`)
- Empty argv
- Invalid argv type or item type (via `validate_stdio_argv`)

Error text includes the server name for diagnosability but never includes
argv contents.

### `MCPServerConfig.argv: tuple[str, ...] | None`

New optional field on the existing frozen dataclass.  Defaults to `None`.
When present, it is a validated non-empty tuple of strings representing the
stdio server process to launch.

### TOML format

```toml
[servers.myserver]
argv = ["python", "-m", "myserver"]
enabled = true
```

`command` and `argv` may coexist in the same server block (backward compat).
