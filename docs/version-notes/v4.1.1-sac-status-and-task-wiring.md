# v4.1.1 sac-status-and-task-wiring

## Summary

v4.1.1 implements T-4.1.1-A (sac-status-cmd) and T-4.1.1-B (wire-edit-apply-rollback-into-task)
from the v4.1–v4.8 shell-first roadmap. All new surfaces are **[EXPERIMENTAL]**.
No stable public contracts are added or changed. `AuditEvent` field set unchanged.

## Changes

### T-4.1.1-A sac-status-cmd

- New `src/safecode/cli_status.py`: `sac status [--json]` shows current task id/goal/status,
  pending patch presence, last test outcome, last command, and one-line "next safe step".
- Pure function `next_step(state, pending_patch_exists)` with full truth-table coverage.
- TTY uses Rich; non-TTY emits deterministic plain text. `--json` uses `CLIJSONResponse`.
- `sac status` never writes audit events.
- Registered in `src/safecode/cli.py`.

### T-4.1.1-B wire-edit-apply-rollback-into-task

- New `src/safecode/task/wiring.py`: helpers for auto-attaching CLI commands to tasks.
- `get_or_create_current_task()`: returns CURRENT task if open; auto-creates if missing/closed.
- `record_edit_on_task()`, `record_apply_on_task()`, `record_rollback_on_task()`,
  `record_fix_on_task()`, `record_run_on_task()`.
- `sac edit`: attaches to CURRENT task; records pending_patch_id and iteration; writes
  `task_edit_wired` audit event with `metadata["task_id"]`.
- `sac apply`: attaches to CURRENT task; sets status=applied; records audit trace id;
  clears pending_patch_id; writes `task_apply_wired` audit event.
- `sac rollback`: attaches to CURRENT task; sets status=open; records audit trace id;
  writes `task_rollback_wired` audit event.
- `sac fix`: attaches to CURRENT task; records iteration with test_command/exit_code/sha.
- `sac run`: attaches to CURRENT task; updates last_command; writes audit event with task_id.
- `AuditLogger.write()` extended with optional `task_id` keyword — stuffed into existing
  `metadata` mapping under key `"task_id"`. No new AuditEvent fields.
