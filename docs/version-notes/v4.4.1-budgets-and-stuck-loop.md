# v4.4.1 — Budgets And Stuck Loop

v4.4.1 continues the experimental v4.4 recovery train with per-task budget configuration and an agent-loop stuck guard.

## Implemented

### T-4.4.1-A task-budget-config

- Added `src/safecode/task/budget.py`.
- Added experimental per-task budget sidecars under `.sac/tasks/budgets/`.
- Defaults: `steps=8`, `time_seconds=600`, `retries=2`, `tokens=60000`.
- Added `sac task budget show [--task <id>] [--json]`.
- Added `sac task budget set [--task <id>] [--steps N] [--time-seconds S] [--retries R] [--tokens T] [--json]`.
- Budget values must be positive integers.
- `AgentLoop.run()` enforces the step budget and records experimental `failure_category: budget_exceeded` with the tripped budget.

### T-4.4.1-B stuck-loop-guard

- `AgentLoop` tracks consecutive identical tool intent identities: `(intent.type, intent.target, intent.tool_name, intent.description)`.
- After three identical consecutive tool intents, the loop aborts with experimental `failure_category: loop_stuck`.
- A structured journal failure event is recorded, and a CURRENT task marker is appended when a task exists.
- Recoverable contract retries are not counted as stuck unless an identical tool intent is actually emitted.

## Contract Status

All v4.4.1 surfaces are EXPERIMENTAL. Budget and stuck-loop categories are not promoted to the v4.7 runtime-wide taxonomy. Command policy, approval, sandbox, and network gates are unchanged.
