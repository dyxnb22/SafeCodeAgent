# v4.17.0 - Streaming Output

## Summary

Wires token-by-token streaming from the LLM layer to the CLI and shell via
Rich Live progressive rendering. `sac ask --stream` and `sac shell` now show
responses as they're generated instead of batch-only.

## Changes

- `llm/stream.py`: `SupportsStreaming` protocol now `@runtime_checkable` for
  safe `isinstance` checks in the orchestrator.
- `agent/orchestrator.py`: new `AgentOrchestrator.ask_stream()` method that
  calls `stream_chat()` on compatible LLM clients, with batch fallback for
  non-streaming clients. Token-level redaction applied per chunk.
- `cli_stream.py` (new): `render_stream()` and `stream_chunks_to_console()`
  helpers using Rich Live for progressive TTY rendering. Non-TTY paths print
  chunks incrementally without Rich.
- `cli_core.py`: `sac ask` gains `--stream` flag. Streams token-by-token in
  TTY mode, falls back to batch for `--json` or non-TTY.
- `shell_session/router.py`: `_handle_ask_intent_stream()` added. Shell ask
  intents stream by default in TTY mode. Non-TTY uses batch `_handle_ask_intent`.

## Tests

- `tests/test_streaming_output.py`: 9 tests covering chunk aggregation,
  orchestrator streaming with fake client, batch fallback, non-TTY rendering,
  and shell router streaming.
