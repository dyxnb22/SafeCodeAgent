# v2.8.4 — MCP Shim Schema Prep (experimental)

## Summary

Adds typed MCP tool schema metadata without implementing real MCP JSON-RPC. Static schemas augment `classify_mcp_tool` keyword matching — when schema metadata is present, the explicit classification is used; when absent, keyword fallback is unchanged.

**Status: experimental.** The schema shim does not contact MCP servers, perform I/O, or implement real JSON-RPC. It is a typed metadata layer only.

## Changes

- **`src/safecode/mcp/schema.py`** (new): `MCPToolSchema` frozen dataclass, `MCPSchemaStore` (in-memory registry), `classify_with_schema()` function.
- **`tests/test_mcp_schema_shim.py`** (new): 30 tests covering schema-present behavior (explicit classification), schema-absent fallback (keyword matching unchanged), server-filter matching, and experimental-boundary verification (no I/O, no subprocess).

## API

```python
from safecode.mcp.schema import MCPToolSchema, classify_with_schema

# Schema overrides keyword
schema = MCPToolSchema(server="myserver", tool="sync_files", classification="write")
classify_with_schema("sync_files", [schema])   # → "write" (from schema)

# No schema → keyword fallback unchanged
classify_with_schema("get_files", [])           # → "read" (keyword match)
classify_with_schema("unknown_op", [])          # → "unknown" (keyword miss)
```

## Acceptance

- `classify_mcp_tool` keyword behavior is unchanged when no schema matches.
- Schema classification takes precedence over keyword when a schema matches.
- No real JSON-RPC implementation.
- 30 new tests prove schema-present and schema-absent paths.
