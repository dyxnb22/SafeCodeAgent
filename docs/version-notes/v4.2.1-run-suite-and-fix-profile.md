# v4.2.1 — sac run --suite and sac fix uses profile

## Summary

v4.2.1 wires the v4.2.0 project profile into the daily loop:
`sac run --suite <kind>` reads the profile and runs the configured command through
the existing ShellRunner/policy path. `sac fix` now consults the profile test command
before falling back to `ProjectTestDetector`. No stable contract changes.

## Tasks

### T-4.2.1-A sac-run-suite

New `--suite test|lint|typecheck|build` option on `sac run`:

- Reads `.sac/project_profile.json` to resolve the command for the given kind.
- If no profile exists: prints "run sac profile detect" guidance and exits 1.
- If the suite kind has no command: prints actionable next-step and exits 1.
- Converts `ProfileCommand.command` tuple to a space-joined string for `ShellRunner`.
- Suite commands are auto-approved (treated as `--yes`) because the user explicitly
  selected the suite; high-risk commands are still blocked.
- Audit events, task sidecar wiring, and exit codes (125/126 per v2.8.8) are
  unchanged from the existing `sac run` path.

### T-4.2.1-B fix-uses-profile

`sac fix` precedence updated:

- `--test-command` explicit override → always wins.
- No `--test-command`, profile exists with a test command → uses profile command.
- No `--test-command`, profile missing or has no test command → `ProjectTestDetector`.
- Profile override is **never** auto-set by `sac fix`; the profile is read-only from
  the fix path.
