# v2.8.2 — Sandbox Backend Strategy Split

## Summary

Separates sandbox backend capability recommendation from `SandboxPlanner` (which adds auditing and plan composition) into a dedicated `SandboxBackendStrategy` class in `src/safecode/sandbox/strategy.py`.

## Changes

- **`src/safecode/sandbox/strategy.py`** (new): `SandboxBackendStrategy` with `recommend()`, `available_backends()`, and `describe()`. Pure functions — no I/O, no audit events, no subprocess calls.
- **`src/safecode/sandbox/planner.py`**: removed inline `_recommend()` method; `SandboxPlanner` delegates to `SandboxBackendStrategy` instead. `self.strategy` attribute exposes the strategy for testing.
- **`tests/test_sandbox_backend_strategy.py`** (new): 20 focused tests covering recommendation priority, available-backend listing, describe, isolation from CLI/planner, and planner delegation.

## Acceptance

- `SandboxBackendStrategy` can be instantiated and called with no project root or config.
- Recommendation logic is deterministic and does not mutate input.
- `SandboxPlanner._recommend()` is removed; planner delegates to `self.strategy`.
- Existing sandbox security evals pass (105 tests).

## Backend Semantics

No backend semantics changed. The priority order (Linux Bubblewrap > macOS Seatbelt > Docker > Noop) is identical to the prior inline implementation.
