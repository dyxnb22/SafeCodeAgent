# v2.6.2 — Release Version Consistency Guard

## Summary

Adds a lightweight guard that detects drift between `pyproject.toml [project].version`
and `safecode.__version__` before a release is tagged.  Motivated by the v2.6.1 incident
where the package metadata stayed at `2.5.1` while the runtime reported `2.6.1`.

No new dependencies (uses stdlib `tomllib`, Python 3.11+).

## Changes

### `src/safecode/release/version_guard.py` (new)

| Symbol | Description |
|---|---|
| `VersionConsistencyResult` | Frozen dataclass: `ok`, `package_version`, `runtime_version`, `message` |
| `check_version_consistency(pyproject_path, runtime_version)` | Reads `[project].version` from pyproject.toml and compares it to `safecode.__version__`; returns a `VersionConsistencyResult` |
| `_find_pyproject(start)` | Walks up from a given directory until pyproject.toml is found |

### `src/safecode/release/__init__.py`

Re-exports `VersionConsistencyResult` and `check_version_consistency`.

### `tests/test_install_update_polish.py`

New `TestVersionConsistencyGuard` class (6 focused tests):
- matching versions → `ok=True`
- mismatched versions → `ok=False` with actionable message quoting both versions
- missing pyproject.toml → `ok=False` with clear message
- malformed pyproject.toml (no version key) → `ok=False`
- result exposes both `package_version` and `runtime_version` fields
- live repo self-check: real pyproject.toml must match `__version__` (regression guard)

## Behavior

```python
from safecode.release.version_guard import check_version_consistency

result = check_version_consistency()  # auto-locates pyproject.toml
if not result.ok:
    raise SystemExit(result.message)
```

Mismatch message example:
```
Version mismatch: pyproject.toml says '2.5.1'
but safecode.__version__ is '2.6.1'.
Update one to match the other before tagging.
```

## Verification commands

```bash
# Focused acceptance tests
PYTHONPATH=src python3 -m pytest tests/test_install_update_polish.py -q

# Full regression
PYTHONPATH=src python3 -m pytest -q
```
