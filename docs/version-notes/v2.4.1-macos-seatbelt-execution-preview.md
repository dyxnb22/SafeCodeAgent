# v2.4.1 — macOS Seatbelt Real Execution Preview

## Summary

Second real sandbox backend execution milestone. macOS Seatbelt (`sandbox-exec`)
proposals now execute when the binary is on `PATH`. Docker and Noop remain
executing; Linux Bubblewrap remains plan-only.

## What Changed

### New: `MacOSSeatbeltExecutor` (`src/safecode/sandbox/seatbelt.py`)
- Rebuilds the `sandbox-exec` profile deterministically from stored
  `SandboxExecutionProposal` fields via `SeatbeltProfileBuilder.build()`.
- Verifies `preview_hash` (`sha256(profile_text)`) before execution — any
  mismatch returns `executed=False` without calling the system.
- Checks `shutil.which("sandbox-exec")` before spawning a subprocess.
- Executes `subprocess.run(["sandbox-exec", "-p", profile_text, *command],
  capture_output=True, shell=False)` — no `shell=True`, no string
  interpolation.
- Returns `SeatbeltExecutionResult` (frozen dataclass: `executed`, `exit_code`,
  `stdout`, `stderr`, `duration_ms`, `message`).
- Fail-closed for all exception paths: hash mismatch, missing binary,
  `TimeoutExpired`, `FileNotFoundError`, `OSError`, and bare `Exception`
  all return `SeatbeltExecutionResult(executed=False, ...)`.

### Updated: `MacOSSeatbeltAdapter.supports_execution()` (`sandbox/adapter.py`)
- Now returns `True` (was `False` in v2.4.0 and earlier).
- `build_plan()` warnings updated to v2.4.1 preview language.

### Updated: `SandboxExecutionGate.execute_pending()` (`sandbox/execution.py`)
- Adds `"macos_seatbelt"` routing block before the Docker branch (after the
  atomic approval claim).
- Delegates to `MacOSSeatbeltExecutor.execute(proposal)`.
- Writes `sandbox_execution_completed` audit event when seatbelt ran (even
  non-zero exit, including macOS 15+ SIGABRT); writes
  `sandbox_execution_blocked` when binary absent or hash-mismatched.
- Writes a result record and clears the pending proposal for all paths,
  matching Docker and Noop lifecycle semantics.

### Updated: `SandboxExecutionPreflight` (`sandbox/preflight.py`)
- Error message for `backend_supports_execution=False` updated: macOS Seatbelt
  is no longer listed as plan-only. Linux Bubblewrap is the only remaining
  plan-only backend.

### Updated: `cli_sandbox.py`
- `sac sandbox status` scope panel updated to v2.4.1.
- macOS Seatbelt row in capability table now shows "executing (preview)".
- `sac sandbox plan` trailing note: Docker and macOS Seatbelt distinguished
  from Linux Bubblewrap (still plan-only).
- Fixed stale "This approval does NOT enable execution" message for the
  approved-but-not-executed display path.

## macOS 15+ Note

On Darwin 25.3.0 (macOS 15+), `sandbox-exec` with user-generated profiles
causes SIGABRT (exit code -6). The executor treats this as a completed
execution (`executed=True`, non-zero exit) — the sandbox profile is being
enforced; the abort reflects OS deprecation of user-profile seatbelt, not a
SafeCode bug. A future release may surface this to the user as a warning.
