# v2.8.7 — Subagent Finding Redaction at Journal Boundary

## Summary

Redact secrets when converting journal events to `SubagentFinding`, before merged context reaches agent loop prompts. Producer-side redaction is primary; consumer-side redaction in `AgentLoop` remains as defense in depth.

## Changes

### Modified

- `src/safecode/subagents/journal_adapter.py` — `_event_to_finding()` now calls `redact_secrets()` on `summary`, each observation string, and each error string before constructing `SubagentFinding`. `files_inspected` is not redacted (paths are metadata, not secret content).
- `src/safecode/agent/loop.py` — `_enrich_with_subagent_findings()` emits a `RuntimeWarning` if consumer-side redaction still changes any merged field, indicating a producer-side gap. Consumer-side pass remains defense in depth.
- `src/safecode/release/versions_sync.py` — `sync_versions_json()` now sorts `merged_tags` by semver so `latest_tags[-1]` always equals the newest tag, preventing out-of-order insertions from retroactive tags.
- `tests/test_subagent_redaction.py` — 10 new tests: `TestJournalBoundaryRedaction` (8 cases covering api_key, bearer token, error secrets, clean pass-through, double-redact stability, malformed payload, files_inspected, multiple events) and `TestConsumerSideRedactionWarning` (2 cases for warning on producer gap and no-warning on clean input).

## Acceptance

- Secret-like strings in summary, observations, and errors become `[REDACTED]` during journal-event-to-finding conversion.
- Merge remains idempotent under already-clean input.
- Agent loop logs a `RuntimeWarning` if consumer-side redaction still changes merged text.
- Malformed journal payloads continue to return `None` (fail closed).
- Existing subagent orchestration behavior unchanged.
- Full regression: 2158 passed, 4 warnings.
