# v3.1.1 — Resume + Retry-From-Failure

## Summary

v3.1.1 adds two session-continuity features on top of the v3.1.0 JSON output substrate:

**resume-session (T-3.1.1-A):** `sac agent resume` now accepts an optional `session_id` argument. When provided, it verifies the current session matches the given ID before resuming. Sessions with `contract_failed` status are refused. Mismatched or missing session IDs exit with code 1.

**edit-retry-from-failure (T-3.1.1-B):** `sac edit --retry-from-last-failure` was already wired in v3.1.0. This version adds focused test coverage via `tests/test_edit_retry.py` and unit tests for `AgentJournalStore.get_last_failure_context()`.

## New Modules

None.

## Modified Modules

- `src/safecode/cli_agent.py` — `agent_resume` gains optional `session_id` argument with contract_failed guard
- `src/safecode/agent/session.py` — `AgentSessionStore.load_by_id(session_id)`

## New Tests

- `tests/test_agent_resume.py` — 9 tests covering load_by_id unit, CLI resume with matching/mismatched ID, contract_failed guard, completed session rejection, no-session case, and no-arg resume
- `tests/test_edit_retry.py` — 8 tests covering failure context injection, secret redaction, no-session fallback, no-failure fallback, task string structure, and last-failure ordering

## Safety

No safety gate was weakened. Resume checks maintain existing approval and status invariants.
