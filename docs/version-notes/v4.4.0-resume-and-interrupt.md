# v4.4.0 — Resume And Interrupt

v4.4.0 starts the experimental v4.4 resume/recovery train.

## Implemented

### T-4.4.0-A sac-resume

- Added top-level `sac resume [<task_id>] [--json]`.
- With an explicit task id, resume loads that task.
- Without a task id, resume uses CURRENT when resumable, otherwise the newest open or interrupted task.
- Closed tasks are refused.
- Interrupted tasks are set back to `open` and made CURRENT.
- Output is passive and redacted: task id, goal, last command, last fix iteration, pending patch state, and next safe step.
- `sac resume` never runs `fix`, `edit`, `apply`, or `run` automatically.

### T-4.4.0-B sigint-durable-interrupt

- `sac edit`, `sac fix`, `sac fix --watch`, and `sac run` now catch `KeyboardInterrupt` only.
- Interrupt handling ensures a task sidecar exists, sets `status=interrupted`, appends an interrupted iteration marker, records journal/audit interruption metadata where available, prints `resume with: sac resume`, and exits 130.
- Pending patch files are not modified by the interruption path.

## Contract Status

All v4.4.0 surfaces are EXPERIMENTAL. No stable public contract was added or promoted, and no `PatchProposal` or `AuditEvent` field sets changed.
