# v2.8.0 diagnostic-core

## Goal
Add the typed diagnostic substrate that doctor, release, and policy checks
can produce internally. Keep the user-facing CLI unchanged.

## Changes
- New: `src/safecode/core/__init__.py` re-exports the public surface.
- New: `src/safecode/core/diagnostic.py`:
  - `DiagnosticStatus` enum: `PASS`, `FAIL`, `WARN`, `SKIP`.
  - `Diagnostic` frozen dataclass: `name`, `status`, `message`, `hints`,
    `metadata`. Convenience constructor `Diagnostic.from_bool()` migrates
    legacy boolean checks.
  - `DiagnosticGroup` frozen dataclass: aggregates diagnostics under one
    label; exposes `status`, `passed`, `failed_diagnostics`, `warnings`,
    `skipped`, `render_lines()`, `as_dict()`.
  - `aggregate_status()` returns the worst severity (PASS < SKIP < WARN < FAIL).
  - `all_passed()` returns True only when every diagnostic is `PASS`
    (empty input passes).
  - All serialisers are deterministic and JSON-friendly.

## Tests
- New: `tests/test_core_diagnostic.py` — 32 tests covering enum values,
  field validation, frozen invariants, hint normalisation, `from_bool`,
  serialisation, aggregation edge cases, and `DiagnosticGroup` behaviour.

## Safety
- Pure data substrate; no CLI side effects, no file IO, no policy
  decisions. Cannot weaken diff/checkpoint/audit/rollback/sandbox gates.
