# v2.6.6 — Git Tag/Version Consistency Guard

## Summary

Extends release consistency checks so the current git tag cannot silently drift from package metadata.

## Changes

- `src/safecode/release/version_guard.py`: added `TagConsistencyResult` dataclass, `get_exact_git_tag()` helper (uses `git describe --exact-match --tags HEAD`), and `check_tag_consistency()` which accepts an explicit `tag=` override for testability.
- `src/safecode/release/check.py`: added `git_tag` parameter to `run_release_check()` (sentinel default auto-detects via git); `ReleaseCheckResult` gains a `tag_result` field; `render_release_check()` displays tag consistency row; next-steps logic updated: correct tag → no redundant suggestion, no tag → suggest tag command, tag mismatch → suggest fix.
- `src/safecode/release/__init__.py`: exports `TagConsistencyResult`, `check_tag_consistency`, `get_exact_git_tag`.

## Test coverage

- `tests/test_release_checklist_polish.py::TestCheckTagConsistency`:
  - matching tag `v2.6.6` vs package `2.6.6` → consistent
  - mismatched tag `v2.6.5` vs package `2.6.6` → not consistent, message names both
  - no tag (`tag=None`) → `consistent=False`, `tag_available=False`, reported honestly
  - `run_release_check` with injected tag includes `tag_result`
  - render output includes tag fields
