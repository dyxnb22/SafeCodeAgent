# v2.9.5 — mcp-call-schema-arg-validation

## Summary

Adds typed argument metadata (`MCPSchemaArg`) to the MCP schema shim and
wires argument validation into `MCPReadOnlyRunner.call_readonly`. When a
tool schema declares `arg_schemas`, calls with missing required arguments
or extra undeclared arguments are rejected with a log-and-block response.
Schema-less workloads (no `arg_schemas`) are completely unaffected.

## Changed Files

- `src/safecode/mcp/schema.py` — adds `MCPSchemaArg` frozen dataclass;
  adds `arg_schemas: tuple[MCPSchemaArg, ...]` field to `MCPToolSchema`;
  adds `validate_call_args(tool_schema, call_args) -> str | None`
- `src/safecode/mcp/runner.py` — `call_readonly` validates args against
  `arg_schemas` after classification; invalid calls are logged and blocked
- `tests/test_mcp_call_schema_arg_validation.py` — 29 new tests
- `pyproject.toml`, `src/safecode/__init__.py` — version bumped to 2.9.5
- `.claude/versions.json`, `.claude/skills/current/SKILL.md` — baseline updated
- `docs/version_implementation_matrix.md` — v2.9.5 row updated

## Constraints Preserved

- No real JSON-RPC client. Validation is pure static metadata checks.
- `arg_schemas == ()` (default) means no arg validation — schema-less behavior unchanged.
- `args: tuple[str, ...]` field (legacy string arg names) is unaffected.
- Invalid payloads fail closed with log evidence and a blocked result; no crash.
- No approval, audit, sandbox, or policy gates weakened.
