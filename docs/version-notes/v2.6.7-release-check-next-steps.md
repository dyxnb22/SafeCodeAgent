# v2.6.7 — Release Check Next-Step Polish

## Summary

Fixes `sac release check` next-step guidance so it does not suggest re-committing or re-tagging when the repo is already in a clean, correctly-tagged state.

## Changes

- `src/safecode/release/check.py`:
  - Added `_summarise_state()` helper — produces a state-specific summary line instead of a generic "All checks passed." catch-all.
  - `render_release_check()` always appends the summary; shows "Ready to release" only when all three signals (version, tree, tag) are confirmed good; shows "git status unknown" when git is unavailable; never claims tests passed.
  - `run_release_check()` next-steps logic (already correct after v2.6.6): clean + correct tag → no suggestions; clean + no tag → tag command only; dirty → stash/commit suggestion; version mismatch → version fix suggestion.

## Test coverage

Added `TestNextStepPolish` to `tests/test_release_checklist_polish.py`:
- dirty tree result has commit/stash suggestion
- version mismatch result has version-fix suggestion
- clean + correctly tagged → no `git commit` or `git tag` in next_steps
- clean + untagged → `git tag` in next_steps, no `git commit`
- render shows "ready" when all checks pass
- render never contains "tests passed" in any state
