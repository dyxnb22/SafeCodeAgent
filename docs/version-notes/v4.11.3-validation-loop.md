# v4.11.3 - Validation Loop

## Summary

Adds an experimental `ValidationLoop` that runs project-profile validation
after successful apply-kind typed steps. The loop executes `test` first and then
configured `lint`, `typecheck`, and `build` suites in deterministic order. On
validation failure it captures a redacted failure tail, computes a stable hash,
records typed validation/repair events, and proposes a repair patch through the
existing `AgentOrchestrator.edit()` path without auto-applying it.

## Changed Files / Modules

- `src/safecode/agent/validation.py`: validation controller, failure-tail
  hashing, repair proposal scheduling, typed journal events, and task iteration
  records.
- `src/safecode/agent/loop.py`: invokes validation after successful apply-kind
  typed results unless validation is disabled.
- `src/safecode/cli_agent.py`: wires `--no-validate` into the loop instance
  while preserving the existing warning behavior.
- `docs/tutorials/agent-run-first-hour.md`: validation walkthrough.
- `tests/test_validation_loop.py`: success, failure-to-fix, no-progress,
  max-iteration, missing-profile, suite-ordering, no-auto-apply, journal, task
  iteration, and no-validate coverage.

## Safety / Contract Note

No new stable contracts promoted. The validation loop remains EXPERIMENTAL,
uses existing profile/ShellRunner/AgentOrchestrator boundaries, never executes a
repair patch, and does not introduce `AgentTaskRunner` or
`src/safecode/agent/task_runner.py`.
