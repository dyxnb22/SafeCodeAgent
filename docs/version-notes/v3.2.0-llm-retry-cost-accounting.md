# v3.2.0 — LLM Retry + Cost Accounting

## Summary

v3.2.0 adds two LLM reliability features on top of the v3.1.1 session-continuity substrate:

**llm-retry-jitter (T-3.2.0-A):** `retry_call()` in `src/safecode/llm/retry.py` wraps any `fn: Callable[[], T]` with bounded retry on `urllib.error.URLError` and `urllib.error.HTTPError` with status 429 or 503. Jitter formula: `uniform(0.5, 1.5) * base_delay * 2^attempt`. Honors `Retry-After` header. Calls `log_fn(attempt, reason)` per retry. Other 4xx/5xx are not retried. Wired into `OpenAICompatibleLLMClient._chat()`.

**llm-cost-accounting (T-3.2.0-B):** `TokenUsage` dataclass and `SessionCostAccumulator` in `src/safecode/llm/cost.py` write per-session token usage to `.sac/sessions/<session_id>/cost.json` atomically. `cost_usd` is always `None` (pricing tables deferred). `OpenAICompatibleLLMClient` optionally accepts `session_id` and `sac_dir`. `sac doctor` shows a `last_session_cost` diagnostic (PASS when cost.json exists, SKIP when not).

## New Modules

- `src/safecode/llm/retry.py` — `retry_call()`, `_parse_retry_after()`
- `src/safecode/llm/cost.py` — `TokenUsage`, `SessionCostAccumulator`

## Modified Modules

- `src/safecode/llm/openai_client.py` — wire `retry_call()` and `SessionCostAccumulator`
- `src/safecode/doctor.py` — `last_session_cost` diagnostic via `_last_session_cost_diagnostic()`

## New Tests

- `tests/test_llm_retry.py` — 17 tests covering retry on 429/503, no-retry on 400/404, exhaustion, Retry-After header, jitter range, log_fn
- `tests/test_llm_cost_accounting.py` — 10 tests covering record/accumulate/load/total, cost_usd=None, sorted keys, doctor integration, client wiring

## Safety

No safety gate was weakened. Retry only on transient transport errors. Cost accumulator failure is silently swallowed — never blocks LLM calls. Mock provider unchanged.
