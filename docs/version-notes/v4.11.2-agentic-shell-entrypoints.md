# v4.11.2 - Agentic Shell Entrypoints

## Summary

Adds experimental agentic entrypoints on existing CLI surfaces:
`sac shell --agentic` routes shell input through `AgentLoop.run()`, and
`sac agent run` gains `--auto-approve-read-only`, `--no-validate`, JSON typed
step output, and a default `--max-steps` of 8. Mutating steps continue to stop
for explicit approval.

## Changed Files / Modules

- `src/safecode/cli_shell.py`: adds `--agentic` mode while preserving the
  existing shell router when the flag is absent.
- `src/safecode/cli_agent.py`: extends `sac agent run` flags, warning behavior,
  JSON envelope, and max-step default.
- `docs/tutorials/agent-run-first-hour.md`: initial walkthrough for the
  agentic loop.
- `tests/test_cli_agent_run.py`, `tests/test_cli_shell.py`, and
  `tests/test_agent_loop_patch.py`: CLI flow, non-TTY fail-closed behavior,
  read-only auto-approval limits, JSON output, and shell integration.

## Tests Run

Focused local evidence: `PYTHONPATH=src python3 -m pytest -q tests/test_cli_agent_run.py tests/test_cli_shell.py`.

Full-suite local evidence: `PYTHONPATH=src python3 -m pytest -q`.

## Safety / Contract Note

No new stable contracts promoted. `sac shell --agentic`, extended
`sac agent run`, `--auto-approve-read-only`, and `--no-validate` remain
EXPERIMENTAL. `--auto-approve-read-only` does not approve edit/apply/run/fix/
commit/rollback steps.
