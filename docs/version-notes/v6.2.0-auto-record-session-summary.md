# v6.2.0 — auto-record-session-summary

## Summary

Implements cross-session project memory (v6.2.x train, step 1).

After every `AgentLoop.run()` call, a bounded, redacted `SessionSummary` is
automatically written to `.sac/memory/sessions.jsonl`. On the next session,
the most recent summaries are loaded and prepended to the agent's context,
giving the agent awareness of what was done in prior sessions.

## What changed

### New modules

- `src/safecode/memory/session_store.py` — `SessionSummary` dataclass and
  `SessionSummaryStore` (append-only JSONL, capped at 50 entries).
- `src/safecode/memory/summary.py` — `build_session_summary()` derives a
  summary from step observations (file touches, commands, test outcomes).
  `format_memory_context()` formats summaries as a bounded context block.

### AgentLoop wiring (`src/safecode/agent/loop.py`)

- `_prepend_session_memory(goal)` — loads recent summaries and prepends them
  to the initial goal string before the first step.
- `_write_session_summary(...)` — called at the end of `run()`; never raises
  (failures are silently swallowed so they cannot break existing workflows).

### New CLI commands (`src/safecode/cli_memory.py`)

- `sac memory inspect [--limit N] [--json]` — human-readable view of recent
  session summaries.
- `sac memory export [--out PATH] [--limit N]` — JSON dump of session
  summaries.

### Tests

- `tests/test_memory_session_store.py` — 38 tests covering:
  `SessionSummary` round-trip, `SessionSummaryStore` append/load/cap/clear/
  export, `build_session_summary` extraction and redaction, `format_memory_context`
  bounds, and `AgentLoop` integration (summary written after run, crash-safety).

## Invariants preserved

- No existing CLI command renamed or removed.
- No safety gate weakened — session memory is injected as context text only;
  it cannot approve, apply, or execute anything.
- Project-local files cannot write session summaries (only `AgentLoop.run()`
  writes them).
- All stored content is passed through `redact_secrets()` before persistence.
- Memory write failures do not propagate — `run()` always returns normally.
