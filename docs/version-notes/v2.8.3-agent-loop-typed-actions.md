# v2.8.3 — Agent Loop Typed Actions

## Summary

Replaces ad hoc `dict[str, object]` pending-action construction (with boolean stringification like `"true"`, `"false"`) in `src/safecode/agent/loop.py` with typed `PendingAction` objects. The loop decides the action; `.to_dict()` serializes it to the session state dict; the CLI rendering layer converts it back.

## Changes

- **`src/safecode/agent/pending_action.py`** (new): `PendingAction` base, `StopForUserAction`, `PatchPendingAction`, `ToolPendingAction`, `pending_action_from_dict()`, `render_pending_action()`.
- **`src/safecode/agent/loop.py`**: all three `pending_action` build sites updated to use typed objects. Imports `StopForUserAction`, `PatchPendingAction`, `ToolPendingAction`.
- **`tests/test_agent_loop_patch.py`**: updated `requires_approval` assertion from `== "true"` to `is True`.
- **`tests/test_agent_session.py`**: updated `executable_now` assertion from `== "true"` to `is True`.
- **`tests/test_agent_loop_typed_actions.py`** (new): 27 tests covering all three action types, round-trip serialization, render output, and loop integration.

## Action Types

| Type | Trigger | Key fields |
|---|---|---|
| `StopForUserAction` | `AgentStopForUserResponse` from LLM | `reason`, `message`, `requires_approval: bool` |
| `PatchPendingAction` | `patch.propose` route | `route`, `requires_approval: bool`, `patch_id`, `files` |
| `ToolPendingAction` | generic routing fallback | `route`, `executable_now: bool`, `requires_approval: bool`, `intent_fields` |

## Acceptance

- No boolean stringification (`"true"`/`"false"`) in pending-action dicts.
- `pending_action_from_dict()` reconstructs typed objects from stored session state.
- Existing agent loop/eval/patch tests pass (41 tests).
- `AgentSessionState.pending_action: dict | None` shape unchanged — backward compatible.
