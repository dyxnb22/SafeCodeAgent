# v3.2.5 — Live-Provider CI Lane

## Summary

Adds an opt-in, advisory CI lane for live provider evaluation that is gated by
a repository variable and skipped by default. Normal CI and the default pytest
invocation are unaffected — no real network calls are made unless explicitly
opted in. No real credentials appear in any repository file.

## What Changed

- `.github/workflows/ci.yml`: added `live-provider` job.
  - Gated by `vars.ENABLE_LIVE_LLM_TESTS == 'true'` (repository variable, not a secret).
  - `continue-on-error: true` — advisory; does not block merges.
  - Sets `SAFECODE_LIVE_TESTS=1`, `ANTHROPIC_API_KEY` and `OPENAI_API_KEY` from secrets.
  - Runs `pytest tests/live/ -v --tb=short` when opted in.
- `tests/live/conftest.py` (new): `pytest_runtest_setup` hook skips all tests in
  this directory unless `SAFECODE_LIVE_TESTS=1`.
- `tests/live/test_live_providers.py` (new): smoke tests for OpenAI-compatible and
  Anthropic providers. Uses `_require_env()` to also skip per-provider if key absent.
- `tests/test_ci_live_lane.py` (new): 21 tests verifying CI structure, live test
  gating, no hardcoded credentials, and default path isolation.

## Design

- Gate: repository variable `ENABLE_LIVE_LLM_TESTS` (not a secret) controls whether
  the job is scheduled. Secrets are injected only when the job actually runs.
- Default pytest (`python3 -m pytest -q`) collects live tests but skips them via
  conftest; 2 skipped are expected in the baseline count.
- No real API keys appear in workflow YAML, test files, or docs.

## Safety / Contract Status

- Normal CI path: unchanged — no credentials required.
- Live lane: advisory only; never blocks merges.
- No provider behavior promoted yet; experimental status maintained.
- Public contract snapshots: unchanged, all pass.
