# v3.2.3 — Anthropic Provider

## Summary

Adds a mocked/tested Anthropic provider behind factory key `anthropic`.
Provider behavior is experimental — not promoted to a public stable contract.
Reuses retry, cost, and streaming infrastructure from v3.2.0–v3.2.1.
No real credentials in tests or CI.

## What Changed

- `src/safecode/llm/anthropic_client.py` (new): `AnthropicLLMClient` implements
  the four-method `LLMClient` contract (`ask`, `plan`, `choose_tool`, `propose_patch`).
  Also implements `SupportsStreaming.stream_chat()`. Uses Anthropic Messages API format
  (`x-api-key`, `anthropic-version`, `content[].text` response extraction,
  `usage.input_tokens`/`output_tokens` for cost accounting). Reuses `retry_call`,
  `SessionCostAccumulator`, `validate_provider_json`, and `parse_sse_stream`.
  `_parse_anthropic_sse` handles Anthropic SSE event types
  (`content_block_delta`, `message_delta`, `message_stop`).
- `src/safecode/llm/factory.py`: added `anthropic` provider key; `create_llm_client`
  lazy-imports `AnthropicLLMClient` to keep the fast path free of the new import.
- `tests/test_llm_anthropic_client.py` (new): 30 tests covering factory selection,
  successful response parsing, malformed response recovery, retry path, cost
  accounting, streaming, and network policy enforcement.

## Design

- `AnthropicLLMClient` is a new concrete class — it does not subclass
  `OpenAICompatibleLLMClient` to avoid coupling their API shapes.
- Retry/cost/streaming modules are imported and reused, not duplicated.
- Prompt caching configuration deferred — usage metadata is recorded when present,
  but `cache_control` headers are not set yet.
- Default provider remains `mock`.

## Safety / Contract Status

- Public contract snapshots: unchanged, all pass.
- OpenAI-compatible provider behavior: not regressed (separate concrete class).
- Provider behavior is experimental: `anthropic` is not in `docs/public-contracts.md`.
- No real API credentials in tests, docs, or CI.
- No real network calls in tests.
