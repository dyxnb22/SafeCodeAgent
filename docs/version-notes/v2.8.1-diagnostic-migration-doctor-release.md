# v2.8.1 diagnostic-migration-doctor-release

## Goal
Migrate the doctor, release, and policy substrates to emit typed
`Diagnostic` objects internally while preserving the legacy CLI surface
and dataclass shapes.

## Changes
- `src/safecode/doctor.py`:
  - `Doctor.run_diagnostics(*, release=False)` returns a typed
    `list[Diagnostic]`.
  - `Doctor.run_release_diagnostics()` returns typed release diagnostics.
  - `Doctor.run()` and `Doctor.run_release()` are backward-compatible
    wrappers that convert diagnostics back to `DoctorCheck`.
  - `DoctorCheck.to_diagnostic()` converts the legacy boolean shape to a
    typed Diagnostic.
- `src/safecode/release/check.py`:
  - `ReleaseCheckResult.to_diagnostics()` produces typed diagnostics for
    `release_check_version`, `release_check_tree`, and `release_check_tag`.
  - Unknown git state surfaces as `SKIP` rather than `FAIL`.
- `src/safecode/release/smoke.py`:
  - New `collect_smoke_diagnostics()` produces a typed list.
  - `SmokeTestCase.to_diagnostic()` and `SmokeTestResult.to_diagnostics()`
    expose the typed view.
  - Internal `_check_*` functions now thread through Diagnostic via
    `_diag_*` helpers; `run_smoke_tests()` builds the legacy
    `SmokeTestResult` from diagnostics.
- `src/safecode/release/preflight.py`:
  - `ReleasePreflightResult.to_diagnostics()` returns one component
    Diagnostic per top-level area (`release_check`, `smoke`, `metadata`,
    `docs`, optional `versions_governance`).
- `src/safecode/release/signoff.py`:
  - `ReleaseSignoffResult.to_diagnostics()` returns
    `signoff_exact_tag`, `signoff_release_check`, and `signoff_preflight`.
- `src/safecode/policy/audit.py`:
  - `PolicyAuditResult.to_diagnostics()` exposes
    `policy_known_names`, `policy_aliases`, `policy_preset_invariants`,
    and an aggregate `policy_audit` diagnostic.

## Tests
- New: `tests/test_diagnostic_migration.py` — 18 tests verifying typed
  diagnostics from doctor, release check, smoke, preflight, signoff, and
  policy audit; round-trips with the legacy dataclasses; and aggregate
  status across substrates.

## Safety
- Public CLI output is unchanged; legacy dataclass fields and properties
  (`ok`, `passed`, `failed`, `next_steps`) preserve their contracts.
- Internal Diagnostic objects do not alter command policy, approval, or
  audit decisions.

## Migration Notes
Sandbox CLI/module split (`v2.8.2`/`v2.8.6`), agent loop typed actions
(`v2.8.3`), MCP shim schema prep (`v2.8.4`), release-surface-collapse-full
(`v2.8.5`), and downstream consolidation versions remain to be tackled in
later sessions per `docs/version-plans/v2.8-to-v3.0-product-architecture-roadmap.md`.
