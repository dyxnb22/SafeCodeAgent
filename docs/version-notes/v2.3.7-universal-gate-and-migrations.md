# v2.3.7 — Universal Tool Gate + State Schema Migrations

## Summary

v2.3.7 adds a universal pre-flight tool gate for write, execute, sandbox, and MCP
CLI paths, plus schema-version migration hooks for key persisted state records.
The release keeps old records readable while failing closed on unsupported future
schema versions.

## What changed

**`src/safecode/tools/gate.py`**
- Added `ToolCallGate`, a no-side-effect wrapper around `ToolCallAdapter`.
- Added `check()` for full validation of tool name, required args, arg types, and approval.
- Added `check_intent()` for CLI entry points where structured args are not available yet.
- Added raising variants `must_pass()` and `must_pass_intent()`.
- Added frozen `GateResult` and `GateError`, a `ValueError` subclass.

**`src/safecode/state/migrations.py`**
- Added `migrate_record(data, record_type)` for persisted state records.
- Missing `schema_version` is treated as v1 for backward compatibility.
- Both `schema_version` and `_schema_version` are accepted as input keys.
- Unsupported future versions raise `SchemaVersionError`.

**State models and stores**
- Added `schema_version: int = Field(default=1)` to `AgentSessionState`,
  `AgentJournalEvent`, and `MCPWriteProposal`.
- `AgentSessionStore.load()`, `AgentJournalStore.read()`, and
  `MCPWriteProposalStore.load_pending()` migrate raw JSON before model construction.
- Future-version journal events are skipped so readable events remain available.
- Future-version session/proposal records return `None`.

**CLI gates**
- `sac edit` checks `patch.propose`.
- `sac apply` checks `patch.apply` after confirmation and before side effects.
- `sac run` checks `shell.run` before command execution.
- `sac rollback --last` checks `checkpoint.rollback`.
- `sac sandbox execute` checks `sandbox.execute`.
- `sac mcp call-readonly` checks `mcp.call_readonly`.
- `sac mcp propose-write` checks `mcp.propose_write`.

## Compatibility

- Existing session, journal, and pending MCP proposal records without
  `schema_version` load as v1.
- Existing read-only CLI paths are unchanged.
- The gate performs validation only; it does not execute commands, write files, or
  call an LLM.
