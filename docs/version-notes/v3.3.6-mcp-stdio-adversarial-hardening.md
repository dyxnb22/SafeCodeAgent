# v3.3.6 — MCP Stdio Adversarial Hardening

## Summary

Adversarial hardening of the v3.3.1-v3.3.5 experimental MCP stdio surface. No new features, no MCP promotion to stable, no change to default runner wiring. All MCP stdio behavior remains experimental.

Adds 37 targeted adversarial tests in `tests/test_mcp_stdio_adversarial.py` covering security properties not explicitly verified in prior versions.

## Security Properties Verified

1. **Server-supplied "classification" field is ignored** — `_parse_tool_entry` hardcodes `classification="unknown"` regardless of what the server sends. A server cannot promote itself to "read" via the JSON response.

2. **CLI `stdio-discover` has no adapter execution path** — `sac mcp stdio-discover` only calls `discover_stdio_tools` (tools/list). `StdioReadOnlyAdapter` is never imported or instantiated by the command. Verified via mock assertions and import inspection.

3. **`--timeout` flag propagates correctly** — `stdio-discover --timeout N` passes `timeout_seconds=N` to `discover_stdio_tools`. Default is 10.0s.

4. **Static classification wins after merge** — When `merge_discovered_schemas` is used to combine static and discovered schemas, the static classification governs in `StdioReadOnlyAdapter`. Static "write" blocks the tool even if discovery found it. Discovered-only tools remain "unknown" and are blocked.

5. **Shell string in TOML config fails at parse time** — `MCPConfigStore.list_servers()` raises `StdioArgvError` when argv is a shell string, non-list, empty, or contains non-string items. Error text never contains the argv values.

6. **Oversized server response fails closed** — Transport-level max_output_bytes enforcement causes discovery to return `success=False`. Error text does not expose server response content.

7. **Error text never contains caller-supplied content** — `StdioReadOnlyAdapter` block/failure errors do not contain `call_args` values. Discovery structural failure error text does not contain server response data.

8. **Shell metacharacter tool names are blocked by classification gate** — Tool names like `"; rm -rf /"`, `"tool\nmalicious"`, and `` "`evil`" `` classify as "unknown" (no static "read" schema), blocking execution before any subprocess is launched.
