# v2.4.3 — Cross-Backend Security Evaluations

**Stage:** v2.4.x Real Sandbox Backends
**Branch:** `v2.4.3-cross-backend-security-evals`
**Key file:** `tests/test_sandbox_cross_backend_security_evals.py`

## Summary

v2.4.3 adds a cross-backend security evaluation suite that verifies security
invariants hold uniformly across all three real execution backends: Docker,
macOS Seatbelt, and Linux Bubblewrap. No new execution backend is introduced.

All 82 new tests are platform-stable: they use injected run functions,
monkeypatched capability detectors, and mocked binary checkers — no real
Docker daemon, sandbox-exec, or bwrap binary is required to run them.

## Security Boundaries Verified

### A. shell=False enforced
Every `subprocess.run` call in `DockerExecutor`, `MacOSSeatbeltExecutor`, and
`LinuxBubblewrapExecutor` must pass `shell=False` explicitly. Tests use
recording run functions and assert on the kwargs.

### B. preview_hash mismatch blocks before binary/daemon check
For Docker: hash mismatch returns before `DockerDaemonChecker.check()` is
called. For Seatbelt and Bubblewrap: hash mismatch returns before
`shutil.which()` is called. Tests verify the downstream check is never reached.

### C. Network disabled by default
- Docker: `--network none` appears in the generated argv.
- Seatbelt: `network-outbound` does not appear in the default profile text.
- Bubblewrap: `--unshare-net` appears in the generated argv.
Tests also verify correct behaviour when network is explicitly enabled.

### D. --privileged never present in Docker argv
`--privileged` must not appear under any combination of options
(writable paths, network enabled, readonly_filesystem=False).

### E. Env values not leaked
Each executor reconstructs `SandboxExecutionRequest` with `env={}`, so
process environment values behind `env_keys` cannot propagate into the
generated argv, profile text, subprocess call, result record, or audit event.

### F. Filesystem boundary: outside-root paths rejected
Writable paths outside the project root must not appear as writable mounts,
bind-writable paths, or write-allow profile rules in any of the three plan
builders.

### G. Sensitive paths not granted write access
Paths containing `.ssh`, `.env`, `.aws`, `credentials`, `token`, or `secret`
segments must be rejected by all three plan builders' writable-mount logic.

### H. Approval claimed atomically before executor invoked
When `claim_for_execution` returns `False`, no executor's `subprocess.run`
is ever called. Tests verify this at the gate integration level for all three
backends.

### I. Result record written and pending cleared
For every terminal execution attempt (success or failure), the gate must
write a result record under `.sac/sandbox_executions/` and remove the pending
proposal file. Tests cover successful injected execution, blocked-claim, and
blocked-binary paths for Docker, Seatbelt, and Bubblewrap.

### J. Env values not in audit records
Env values must not appear in any audit event's `message` or `metadata` fields,
nor in the persisted result record JSON, for any real backend.
