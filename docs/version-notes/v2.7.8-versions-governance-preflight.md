# v2.7.8 versions-governance-preflight

## Goal
Connect the v2.7.2 versions-json sync into release governance: make `sac release preflight` fail when versions.json is stale or SKILL.md has conflicting baseline tags.

## Changes
- `src/safecode/release/versions_governance.py` (new): `check_versions_governance()` checks:
  1. `.claude/versions.json` `current_implemented_tag` matches latest git tag.
  2. `.claude/skills/current/SKILL.md` has exactly one `Implemented. Git baseline: tag` entry (no contradictions).
  - On stale versions.json: issues include `sac release sync-versions-json` next step.
  - `git_tags` can be injected for testing without a real git repo.
- `src/safecode/release/preflight.py` updated:
  - `ReleasePreflightResult` gains `versions_governance: VersionsGovernanceResult | None`.
  - `run_release_preflight` gains `versions_governance_runner` injectable.
  - `render_release_preflight` shows `[PASS/FAIL] versions governance` and lists issues.
- `tests/test_release_preflight.py`: all calls updated to pass `versions_governance_runner` stub.
- `tests/test_versions_governance_preflight.py`: 11 new tests covering stale/current/missing versions.json, single/double/missing baseline tags, real repo check, and preflight integration.

## Tests
- `tests/test_versions_governance_preflight.py`: 11 new tests, all passing.
- Updated `tests/test_release_preflight.py`: 10 tests, all passing.

## Safety
Governance check is read-only. Injected git_tags parameter allows fixture-based testing without requiring the real repo state.
