## Completion Notes
- `src/safecode/agent/web_fetch_tool.py` (new):
  - `_MaxRedirectHandler`: limits redirects to 3; raises HTTPError on excess.
  - `_strip_html(html)`: removes `<script>` and `<style>` blocks, strips all tags, collapses whitespace.
  - `_fetch_url(url, max_bytes)`: validates scheme (http/https only), performs GET via custom opener, checks Content-Type (text/* only), reads up to max_bytes, applies `_strip_html` for HTML, applies `redact_secrets()`. URL never appears in error messages (B12 pattern).
  - `_web_fetch_handler(call_id, inp)`: validates url input, checks `config.sandbox.network_enabled` (blocked by default), calls `_fetch_url()`.
  - `WEB_FETCH_SPEC`: `NativeToolSpec(name="web_fetch", requires_approval=False, audit_event_type="tool_call_read")`.
  - `register_web_fetch_tool(dispatcher, project_root)`: registers handler with injected project_root.
  - `SafeCodeConfig` imported at module level for patchability in tests.

## Safety Invariants
- Only `http://` and `https://` URLs accepted; `file://`, `ftp://`, etc. → blocked.
- `network_enabled=False` (default) → blocked; no network access without explicit opt-in.
- Content-Type must start with `text/`; binary/JSON → blocked.
- HTML `<script>` and `<style>` stripped before returning to model context.
- Output capped at `max_bytes` (default 50 000).
- At most 3 redirects; excess → error.
- URL never appears in error messages.
- `redact_secrets()` applied to all output.
