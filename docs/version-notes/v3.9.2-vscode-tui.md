# v3.9.2 — VS Code Extension VSIX + TUI Decision

## Summary

Externalizes the VS Code extension to `vscode-extension/` with a TypeScript
entrypoint, package.json, and build script. Decides TUI freeze at experimental.

## T-3.9.2-A: VS Code Extension Package

**VSIX build deferred.** `tsc` is not available in the current build environment.
The extension source is fully written and manifest-tested; manual VSIX smoke
requires Node.js + npm install + tsc.

**Manual VSIX smoke procedure (deferred):**

```bash
cd vscode-extension
npm install
npm run build    # requires tsc
npm run package  # requires @vscode/vsce
# Install the generated .vsix in VS Code:
# code --install-extension safecode-agent-3.9.2.vsix
```

**Changes:**
- `vscode-extension/package.json`: VS Code extension manifest with 6 commands
  (`safecode.ask`, `safecode.edit`, `safecode.apply`, `safecode.rollback`,
  `safecode.openDiff`, `safecode.apiJsonrpc`), `_safecodeNotes` documenting
  JSON-RPC contract version, launch command, zero telemetry, and modal approval
  gate.
- `vscode-extension/src/extension.ts`: TypeScript entrypoint; spawns
  `sac api jsonrpc` as a child process over stdio; JSON-RPC 2.0
  (newline-delimited); approval prompt is a VS Code modal (`showWarningMessage`
  with `{ modal: true }`); no telemetry; no marketplace publish in this batch.
- `vscode-extension/tsconfig.json`: CommonJS target, ES2020, strict mode.
- `vscode-extension/.vscodeignore`: excludes src, node_modules from package.
- `tests/test_ide_extension_manifest_contract.py` (new): 24 tests across 6
  classes — package.json shape, command parity with `ide/manifest.py`, JSON-RPC
  transport parity (contract version, launch command, supported methods), safety
  invariants (no telemetry imports, approval modal present, experimental label),
  and VSIX build script presence.

## T-3.9.2-B: TUI Decision

**Decision: Option B — freeze `sac tui interactive` at v3.5.2 behavior.**

**Rationale:** No Textual patterns or dependencies exist in the codebase. Adding
Textual would require a new dependency, a richer test harness, and significant
effort to cover plan/diff/approval/journal-tail without adding new safety surface.
The current Rich-based TUI is deterministic, testable, and CI-safe. The surface
is labeled EXPERIMENTAL and will not be promoted to a stable contract without a
full redesign pass.

**Changes:**
- `docs/public-contracts.md`: TUI experimental table entry updated to "Frozen
  experimental at v3.9.2"; IDE bridge entry updated to note VSIX deferral.
- `tests/test_tui_interactive_smoke.py`: `TestTUIFrozenExperimental` class (5
  tests) — verifies TUI still exits 0, still labeled experimental, no Textual
  import, public-contracts.md says "frozen", output still has "SafeCode TUI".
