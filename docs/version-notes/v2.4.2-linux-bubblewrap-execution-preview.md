# v2.4.2 — Linux Bubblewrap Real Execution Preview

## Summary
Adds real bwrap execution to the Linux Bubblewrap sandbox backend.
All four backends (Noop, Docker, macOS Seatbelt, Linux Bubblewrap) now support
the full propose → approve → execute lifecycle.

## Changes

### `src/safecode/sandbox/bubblewrap.py`
- Added `BubblewrapExecutionResult` (frozen dataclass).
- Added `LinuxBubblewrapExecutor`: rebuilds bwrap argv via `BubblewrapArgsBuilder`,
  verifies `preview_hash` (sha256 of stable JSON argv), checks `bwrap` on PATH via
  `shutil.which`, then calls `subprocess.run(argv, capture_output=True, shell=False)`.
  Never raises — all failure paths return `executed=False`.

### `src/safecode/sandbox/adapter.py`
- `LinuxBubblewrapAdapter.supports_execution()` now returns `True`.
- `build_plan()` warnings updated to v2.4.2 language; limitations updated to reflect
  execution-capable status.

### `src/safecode/sandbox/execution.py`
- `SandboxExecutionGate.execute_pending()`: added `linux_bubblewrap` routing block
  before the macOS Seatbelt block. Writes `sandbox_execution_completed` /
  `sandbox_execution_blocked` audit event; writes result record and clears pending
  for all paths.

### `src/safecode/sandbox/preflight.py`
- Removed stale "Linux Bubblewrap is still plan-only in v2.4.x" text from the
  `backend_supports_execution` failure reason.

### `src/safecode/cli_sandbox.py`
- `sac sandbox status`: scope panel updated to v2.4.2; Linux Bubblewrap Mode column
  changed from `plan-only` to `executing (preview)`.
- `sac sandbox plan`: added `LINUX_BUBBLEWRAP` case to `backend_mode` mapping;
  dry-run panel now lists all three executing backends and uses v2.4.2 text.

## Security Boundaries Preserved
- `shell=False` enforced in all `subprocess.run()` calls.
- Network disabled by default (`--unshare-net` in bwrap argv) unless
  `proposal.network_enabled=True`.
- Filesystem boundary validation via `BubblewrapArgsBuilder` (sensitive path
  detection, project root containment, blocked writable roots).
- No broad host writes: `BubblewrapArgsBuilder` rejects paths outside project root
  and paths matching sensitive segments.
- No env value leakage: `env={}` passed when reconstructing the request.
- `preview_hash` verified before execution — hash mismatch always blocks.

## Tests
`tests/test_bubblewrap_executor.py` — 34 new tests covering:
- Executor success path (injected run_fn)
- Executor fail-closed paths: hash mismatch, missing bwrap (shutil.which and
  FileNotFoundError), timeout, OSError, argv reconstruction failure
- `shell=False` assertion
- Audit event and result record lifecycle via `SandboxExecutionGate`
- Noop, Docker, and macOS Seatbelt backend regressions
- `LinuxBubblewrapAdapter.supports_execution()` is now `True`
- Updated CLI honesty text checks
