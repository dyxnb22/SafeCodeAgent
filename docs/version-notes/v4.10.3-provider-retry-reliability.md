# v4.10.3 — Provider Retry Reliability

## Summary

Hardens `OpenAICompatibleLLMClient` with rate-limit-aware retry, configurable
per-call timeout, and structured progress callbacks. On HTTP 429 or transient
5xx responses the client backs off with bounded exponential delay and retries
up to a configurable limit (default 3). Per-call timeout defaults to 60 s and
is config-overridable. A structured progress callback fires at each retry
attempt so callers can surface "retrying…" messages without coupling to
internals. All retry/timeout parameters are bounded and validated at
construction time.

## Changed Files / Modules

- `src/safecode/llm/openai_client.py`: retry loop, timeout parameter,
  progress callback, 429/5xx detection.
- `src/safecode/config.py`: `llm.max_retries` and `llm.timeout_seconds`
  config fields (optional, bounded).
- `tests/test_llm_retry_handling.py`: 429 retry, 5xx retry, max-retry
  exhaustion, timeout, progress callback, no-retry on 4xx, backoff
  ordering tests.

## Tests Run

## Safety / Contract Note

No new stable contracts promoted. All new surfaces are EXPERIMENTAL.
Retry logic never bypasses network policy; secret keys are never logged,
echoed, or written to disk during retry.
