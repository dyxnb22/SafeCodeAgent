# v2.6.4 — Policy Preset Docs/Examples Hardening

## Summary

Updates `README.md` and `docs/install-update.md` so users have a single,
accurate reference for policy preset names, legacy aliases, env-var behavior,
and the safety invariants that hold across all presets.

No behavior changes — v2.6.0 and v2.6.1 semantics are preserved exactly.

## Changes

### `README.md`

New **Policy Presets** section added between _Safety Defaults_ and _Debug Runtime Logs_:
- Table of canonical names (`strict`, `balanced`, `experimental`) and legacy aliases (`normal`, `learning`).
- `sac setup --policy <name>` usage examples.
- `.sac/config.toml` and `SAFECODE_POLICY` env-var examples.
- Full list of safety invariants (block_high_risk always True, network always off, unknown env var warned/ignored, project config cannot override user policy).

### `docs/install-update.md`

Extended the _First Setup_ section with:
- `sac setup --policy <name>` examples for all three canonical names.
- Clarification that legacy aliases `normal` and `learning` are accepted.
- Note on unknown `SAFECODE_POLICY` values (warn and ignore).
- Note that unknown project-config policy names cannot override known user policy.

## Policy reference (authoritative)

| Name | Type | Order | Notes |
|---|---|---|---|
| `strict` | canonical | 2 (strictest) | Minimal commands, all confirms |
| `balanced` | canonical | 1 | Default balance |
| `experimental` | canonical | 0 (most permissive) | Wide commands, fewer confirms |
| `normal` | legacy alias | 1 | Same as `balanced` |
| `learning` | legacy alias | 0 | Same as `experimental` |

### Invariants (unchanged from v2.6.0/v2.6.1)

- `shell.block_high_risk = True` in every preset.
- `sandbox.restrict_to_project_root = True` in every preset.
- `sandbox.network_enabled = False` in every preset.
- `SAFECODE_POLICY` can only raise effective policy, never lower it.
- Unknown `SAFECODE_POLICY` value → `UserWarning` + ignored.
- Unknown project-config policy name → does not override known user policy.
