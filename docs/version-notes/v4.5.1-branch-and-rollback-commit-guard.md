# v4.5.1 - branch and rollback commit guard

## Status

Implemented. All v4.5.1 surfaces are EXPERIMENTAL. No stable public contracts were promoted.

## What changed

- Added `sac branch new <name> [--json]`.
- Branch creation validates names with SafeCode checks and `git check-ref-format --branch`.
- Branch creation refuses empty, whitespace-only, shell-metacharacter, existing, and dirty-unrelated cases.
- Branch creation never force-creates and never resets.
- Added rollback-after-commit warning for `sac rollback --last`.
- When the latest checkpoint files appear committed, rollback refuses by default and prints a `git revert <sha>` hint.
- Added explicit `--force-uncommit` to allow rollback after the committed-apply warning.
- `--force-uncommit` emits an audit event with the detected commit sha when available.

## Safety notes

- Default rollback-after-commit behavior never rewrites git history.
- If checkpoint files still have uncommitted worktree changes, rollback behavior remains unchanged.
- No `PatchProposal` or `AuditEvent` field sets changed.
