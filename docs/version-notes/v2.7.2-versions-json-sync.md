# v2.7.2 versions-json-sync

Fixes version governance drift by providing an automated sync command and staleness detection.

## Changes

- **New `src/safecode/release/versions_sync.py`**: Provides `sync_versions_json()` and
  `check_versions_json_stale()`. The sync is additive — new git tags are appended to `latest_tags`
  without discarding the curated history. `current_implemented_tag` is updated to the latest
  git tag. Supports `dry_run=True` to check without writing.
- **New CLI command `sac release sync-versions-json`**: Runs the sync against the current repo.
  `--dry-run` reports without writing. Exits 1 on error (missing versions.json, no git tags).
- **New test file `tests/test_versions_json_sync.py`** (9 tests): Covers stale detection, additive
  append, current tag updates, dry run, missing versions.json, no-tags error, and a live check
  that the repo's own versions.json is not stale.

## Acceptance

- `PYTHONPATH=src python3 -m pytest tests/test_versions_json_sync.py -v` → 9 tests pass.
- `PYTHONPATH=src python3 -m pytest -q` → 1881 tests pass.
- Stale versions.json (current_implemented_tag behind latest git tag) is detected as `changed=True`.
- No hardcoded version strings in the sync logic.
