# v3.3.0 — MCP stdio Transport

## Summary

Adds a real but tightly-bounded stdio JSON-RPC transport for MCP-style calls,
tested only against local stub servers.  Not wired into the existing MCP runner;
integration is a future step.  MCP remains experimental after this version.

## New file

`src/safecode/mcp/transport_stdio.py` — standalone stdio JSON-RPC client.

## Key properties

- `call_stdio(argv, method, params, ...)` — sends one JSON-RPC request, reads one response.
- `argv` list only; never `shell=True`.
- Timeout enforced; process killed on expiry (exit code 124).
- Max output size enforced; fails closed on excess (exit code 126).
- Fails closed on: malformed JSON, id mismatch, timeout, process exit without output.
- stderr captured and truncated to `_MAX_STDERR_BYTES` (4096); never placed in `error` field.
- Caller-supplied `params` content never copied into error messages.
- Returns `StdioTransportResult` (frozen dataclass); never raises.

## Tests

`tests/test_mcp_transport_stdio.py` — 45 tests using local stub Python server scripts in `tmp_path`.
Covers: round-trip, id mismatch, malformed JSON, timeout + cleanup, process exit, oversized output,
argv/no-shell, stderr truncation, secret-payload non-leakage.

## Invariants preserved

- No existing MCP runner behavior changed.
- No MCP contract promoted.
- Existing MCP schema classification and arg validation unchanged.
- No network; no real external MCP server.
