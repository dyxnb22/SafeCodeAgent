# v3.9.0 — Signing Truthing + TestPyPI Rehearsal

## Summary

Aligns `sac release publish` signing semantics with the actual implementation
and adds a `--repository test-pypi` lane for upload rehearsal.

## T-3.9.0-A: Signing Truthing

**Decision: Option B** — rename `--sign` semantics throughout code, docs, and
threat model to "detached cosign or gpg signature."

**Rationale:** The implementation already uses `cosign sign-blob` or
`gpg --detach-sign --armor` — a plain detached signature placed alongside each
artifact. There is no Sigstore Rekor transparency-log entry. Implementing real
Sigstore (Option A) would require network access during release, additional
dependencies, and keyless-signing infrastructure decisions that are out of scope
for this batch. Option B is honest and immediately verifiable.

**Changes:**
- `src/safecode/release/publish.py`: module docstring and `_planned_steps()` now
  explicitly say "detached signature via cosign (sign-blob) or gpg (--detach-sign
  --armor)". The `_check_sign_tooling()` error message also references the
  detached-signature mechanism.
- `docs/install-update.md`: new "Release Signing" section documents the
  detached-signature approach and explicitly states this is not Sigstore Rekor.
- `docs/security/threat-model-v3.6.md`: new "Release Artifact Integrity" subsection
  documents the signing mechanism, the `SAFECODE_PUBLISH=1` gate, and the
  TestPyPI rehearsal path.
- `tests/test_release_publish_dry_run.py`: `TestSigningMechanismDescription` (6
  tests) — dry-run step mentions "detached", names cosign/gpg, does not mention
  "rekor", and render output includes the repository label.

## T-3.9.0-B: TestPyPI Rehearsal

**Changes:**
- `src/safecode/release/publish.py`: new `repository` parameter on
  `run_release_publish()` and `PublishResult`; `_REPOSITORY_URLS` dict maps
  `"pypi"` and `"test-pypi"` to their upload URLs; real upload uses
  `uv publish --publish-url <url>`; real test-pypi upload still requires
  `SAFECODE_PUBLISH=1` + clean tag.
- `src/safecode/cli_ops.py`: `--repository` option on `sac release publish`;
  JSON output includes `repository` field.
- `docs/install-update.md`: "TestPyPI Rehearsal" section with dry-run command,
  real-upload command, and pipx install from TestPyPI; also adds pipx install
  and offline wheel install recipes.
- `tests/test_release_publish_repository.py` (new): 28 tests across 7 classes
  covering URL registry, dry-run with repository, unknown repository failing
  closed, real-publish gating for test-pypi, planned-step labels, result field,
  and CLI option.
