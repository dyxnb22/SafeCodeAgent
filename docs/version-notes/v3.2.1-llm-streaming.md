# v3.2.1 — LLM Streaming

## Summary

Adds provider-level streaming support as an opt-in capability extension.
Existing non-streaming behavior is unchanged. Provider behavior remains
experimental and is not promoted to a public stable contract.

## What Changed

- `src/safecode/llm/stream.py` (new): `StreamChunk`, `StreamResult`,
  `StreamError`, `aggregate_chunks()`, `parse_sse_line()`, `parse_sse_stream()`,
  and `SupportsStreaming` protocol.
- `src/safecode/llm/openai_client.py`: added `stream_chat(messages, *, _lines_fn=None)`
  and `_http_stream_lines()`. Uses `_lines_fn` injection for tests (no real network).
- `src/safecode/llm/mock.py`: added `stream_chat()` that yields a single chunk.
- `tests/test_llm_streaming.py` (new): 31 tests covering chunk aggregation,
  final output equivalence, malformed event handling, retry non-duplication,
  session state integrity, and non-streaming backward compatibility.

## Design

- `SupportsStreaming` is a separate protocol from `LLMClient` — providers opt in
  without breaking the base contract.
- `stream_chat` fails closed on malformed SSE events (raises `StreamError`).
- Partial stream cancellation does not mutate session cost state.
- Default provider remains `mock`; network policy is enforced before real calls.

## Safety / Contract Status

- Public contract snapshots: no change.
- No safety gates weakened.
- Provider streaming behavior is experimental — not in `docs/public-contracts.md`.
- No real network calls in tests.
