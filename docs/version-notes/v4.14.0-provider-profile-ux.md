# v4.14.0 - Provider Profile UX

v4.14.0 improves the model/provider setup path so users configure SafeCode by
provider profile first, then switch models with short aliases. DeepSeek profile
setup can persist trusted user-level API key and network policy, `sac model`
resolves provider aliases such as `flash` and `pro`, and shell/provider status
surfaces show the effective provider, model, key source, and network policy.

| Claim | Implementation |
|---|---|
| Provider-oriented configuration | `sac provider add/list/status/use/rm` manages trusted user profiles under `[providers.<name>]` |
| Short model switching | `sac model flash`, `sac model pro`, and scoped aliases update the active provider default model |
| One-shot model override | root `sac --model ...` and `sac shell --model ...` set the model for a single invocation |
| Diagnostics match profile UX | `sac doctor` and live smoke prechecks recognize trusted user config keys as well as env vars |
| Tests isolated from real user config | pytest autouse fixture redirects `SAFECODE_USER_CONFIG` and clears real provider key env vars for non-live tests |
| No new stable contracts | Provider-profile UX remains an experimental v4 surface |
