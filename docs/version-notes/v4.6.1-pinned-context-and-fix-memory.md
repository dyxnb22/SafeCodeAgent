# v4.6.1 - pinned context and fix memory

## Status

Implemented. All v4.6 memory/context surfaces are EXPERIMENTAL. No stable public contracts were promoted.

## What changed

- `ContextSelector` now reads pinned files from `MemoryFacade`.
- Safe pinned files are considered even when they do not match the query.
- Pinned files are capped by a bounded selector quota and do not replace keyword-selected files entirely.
- Missing pinned files expose deterministic `pinned_missing` warning metadata, surfaced by `ContextCollector` under `selected_context.warnings`.
- Ignored, sensitive, binary, and root-escaping pinned files remain excluded by existing safe context gates.
- `sac fix` and `sac fix --watch` record redacted recent failures through `MemoryFacade`.
- Recent failures keep only the newest 200 entries.
- The prompt sent to `AgentOrchestrator.edit()` includes the newest three recent failures as bounded task context.

## Safety notes

- Pinned files do not bypass context redaction, sensitive-file filtering, binary-file filtering, or project-root boundaries.
- Recent failure entries store redacted bounded tails and hashes, not raw unbounded command output.
- Existing `edit --retry-from-last-failure` behavior remains available.
- No project profile precedence changed.
- No `PatchProposal` or `AuditEvent` field sets changed.
