# v2.6.1 — Migration Hardening

## Summary

Hardens migration behavior around policy names introduced in v2.6.0.  Unknown policy names from project config or the `SAFECODE_POLICY` env var are now handled explicitly rather than silently falling through.  `write_setup()` (and `sac setup`) now accept all five recognized policy names.  No new dependencies.

## Changes

### `src/safecode/config.py`

| Symbol | Change |
|---|---|
| `KNOWN_POLICY_NAMES: frozenset[str]` | New — all five recognized names (`strict`, `balanced`, `experimental`, `normal`, `learning`) |
| `is_known_policy_name(name) -> bool` | New — returns `True` iff name is in `KNOWN_POLICY_NAMES` |
| `_stricter_policy(left, right)` | Updated — unknown `right` never overrides a known `left`; unknown `left` is compared conservatively as `balanced` (order=1) |
| `SafeCodeConfig.load()` | Updated — unknown `SAFECODE_POLICY` value issues a `UserWarning` and is ignored instead of being silently applied as balanced-equivalent |

### `src/safecode/setup.py`

- `write_setup(policy=...)` now accepts all five recognized policy names (previously only `{"learning", "normal", "strict"}`).
- Error message updated to list the full set of valid names.

### `src/safecode/cli.py`

- `sac setup --policy` help text updated to mention the three canonical names plus legacy aliases.

## Behavior changes

### Unknown right-side policy names

Before v2.6.1, `_stricter_policy()` used `POLICY_ORDER.get(name, 1)` for both sides, so an unknown project config policy (not in `POLICY_ORDER`) was silently treated as `balanced`-equivalent and could override a user `experimental` policy.

After v2.6.1:
- Unknown `right` (project config policy) → always return `left` (user policy is preserved).
- Unknown `left` (user config policy) → compare conservatively as `balanced` (order=1); if project is stricter, project wins.
- Both unknown → return `left`.

### SAFECODE_POLICY env var

Before v2.6.1, an unknown value like `SAFECODE_POLICY=future_policy` was applied via `_stricter_policy()` with the silent default order=1.

After v2.6.1, unknown values issue a `UserWarning` and are ignored:
```
UserWarning: SAFECODE_POLICY='future_policy' is not a recognized policy name
             (known: ['balanced', 'experimental', 'learning', 'normal', 'strict']); ignoring.
```

Known aliases (`normal`, `learning`) continue to work without warnings.

### write_setup() now accepts canonical names

```python
# v2.6.0: raises ValueError
write_setup(project_root, policy="balanced")
write_setup(project_root, policy="experimental")

# v2.6.1: accepted
write_setup(project_root, policy="balanced")
write_setup(project_root, policy="experimental")
```

## Invariants preserved

- `block_high_risk` and `restrict_to_project_root` remain `True` in all merged configs regardless of unknown policy names.
- `network_enabled` defaults to `False` for all presets; project config cannot enable it if user disables it.
- `SAFECODE_POLICY` can only raise effective policy, never lower it — unknown values are now explicitly skipped.
- Legacy aliases `normal` and `learning` continue to work identically to `balanced` and `experimental` respectively.
