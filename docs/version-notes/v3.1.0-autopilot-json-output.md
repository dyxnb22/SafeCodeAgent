# v3.1.0 — Autopilot + JSON Output

## Summary

v3.1.0 adds two productization features on top of the v3.0.0 stable safety substrate:

**json-output-foundation (T-3.1.0-A):** Every daily CLI command now supports a `--json` flag that emits a structured, deterministic JSON object instead of Rich terminal output. Covered commands: `sac ask`, `sac edit`, `sac apply`, `sac run`, `sac doctor`, `sac version`, `sac release preflight`. JSON output is implemented via a shared `CLIJSONResponse` Pydantic model in `src/safecode/cli_shared_json.py`. All non-JSON output paths are byte-compatible with v3.0.0.

**autopilot-agent-run (T-3.1.0-B):** The existing `sac agent run "goal"` command is confirmed as the autopilot entry point, driving `AgentLoop.run()` to completion or stop-for-user under all existing approval gates. `sac agent run --json` emits structured JSON with `session_id`, `stopped_reason`, and `steps_count`. No approvals are bypassed.

**edit --retry-from-last-failure foundation:** `sac edit` now accepts `--retry-from-last-failure`, which reads the most recent failure event from the session journal, redacts it through `redact_secrets()`, and prepends it to the task context. The journal helper `get_last_failure_context()` is also added to `AgentJournalStore`.
