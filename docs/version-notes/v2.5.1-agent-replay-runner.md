# v2.5.1 — Agent Replay Runner

**Stage:** v2.5.x Reliability and Evaluation
**Branch:** `v2.5.1-agent-replay-runner`
**Key file:** `src/safecode/eval/runner.py`

## Summary

v2.5.1 adds the first deterministic replay runner layer for `TaskEvalFixture`.
No real LLM is invoked: `repo.setup_commands` simulate what an agent applied,
and `validation_commands` verify the resulting workspace state.

The old `EvalRunner` / `EvalCase` / `EvalResult` surface (v2.4.x baseline) is
preserved unchanged in the same module. Real agent/LLM replay hooks can be
injected in a future layer by subclassing or wrapping `TaskReplayRunner`.

68 new tests in `tests/test_task_eval_runner.py` across 18 classes.

## Domain Model (`src/safecode/eval/runner.py`)

### `WorkspaceError(RuntimeError)`
Raised during workspace materialisation or `setup_commands` if the workspace
cannot be prepared. Caught by `TaskReplayRunner.run()` and converted into a
failed `ReplayResult` with `error` populated.

### `ValidationCommandResult` (frozen dataclass)
Result of one validation command: `command`, `exit_code`, `stdout`, `stderr`,
`passed` (`exit_code == 0`), `failure_reason`.

### `ReplayResult` (dataclass)
Full result of a fixture replay.

| Field | Description |
|---|---|
| `fixture_name` | From `fixture.name` |
| `passed` | `True` iff all constraints satisfied and no safety violations |
| `failure_reasons` | All individual violation strings |
| `validation_details` | Per-command `ValidationCommandResult` list |
| `observed_changed_files` | Files changed by `setup_commands` vs initial state |
| `workspace_diff` | Unified diff text across all changed files |
| `network_intent` | `"allowed"` or `"denied"` from `safety.allow_network` |
| `forbidden_commands_violated` | `safety.forbidden_commands` patterns found in validation_commands |
| `forbidden_file_writes_violated` | `safety.forbidden_file_writes` patterns found in changed files |
| `audit_events_status` | `"ok"` or `"pending_no_session_replay_source"` |
| `workspace_path` | Path to temp dir during the run (cleaned up after) |
| `error` | Set when workspace materialisation failed |

### `TaskReplayRunner`

**Execution flow:**

1. Materialise a temporary workspace from `fixture.repo`:
   - `kind="inline"`: write `repo.files` dict to temp dir; nested paths created.
   - `kind="local"`: `shutil.copytree` source into temp dir; source never mutated.
2. Snapshot initial file state (before any commands).
3. Run `repo.setup_commands` — these simulate what the agent applied.
   A failed setup command records the error in `failure_reasons` and continues
   to the validation phase.
4. Snapshot final file state; compute unified diff and changed-file list.
5. Run `fixture.validation_commands` with per-command timeout
   (`min(fixture.timeout_seconds, 60)`). Timed-out commands return exit code 124.
6. Evaluate all constraints:
   - `expected.expected_exit_code`: if set, last command must match; if absent,
     all commands must exit 0.
   - `expected.expected_output_contains`: checked against combined stdout+stderr.
   - `expected.expected_diff_contains`: checked against unified diff text.
   - `expected.expected_files_changed`: each file must appear in changed list.
   - `fixture.expected_changed_files`: each file must appear in changed list.
   - `fixture.forbidden_changed_files`: each file must NOT appear in changed list.
7. Safety checks:
   - `safety.forbidden_file_writes`: matched against observed changed files.
   - `safety.forbidden_commands`: matched against validation commands run
     (best-effort in this layer; full agent command history requires a live session).
   - `safety.allow_network`: recorded in `network_intent`; enforcement is future work.
   - `safety.expect_audit_events`: non-empty → `audit_events_status =
     "pending_no_session_replay_source"`. Does NOT cause a failure — reported
     clearly so the caller knows audit verification was not attempted.
8. Return `ReplayResult`; clean up temp dir.
