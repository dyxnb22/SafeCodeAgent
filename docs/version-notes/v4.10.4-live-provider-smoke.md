# v4.10.4 — Live Provider Smoke

## Summary

Adds `sac smoke live-provider` — an opt-in, gated smoke scenario that makes a
real network call to the configured provider and verifies a minimal chat
completion response. The command is hidden from `sac --help` (accessible but
not shown), requires `SAFECODE_LIVE_SMOKE=1` to be set (fail-closed without
the flag), and records the round-trip latency without storing response content.
The existing `sac smoke shell-first` and `sac smoke ai-shell` scenarios remain
mock-only and are unaffected.

## Changed Files / Modules

- `src/safecode/cli_smoke.py`: `live-provider` scenario with `SAFECODE_LIVE_SMOKE`
  gate and latency recording.
- `tests/test_smoke_live_provider.py`: gate enforcement (fails closed without
  env var), mock-path smoke, latency-recorded assertion,
  and existing-scenarios-unchanged tests.

## Tests Run

Targeted: `tests/test_smoke_live_provider.py` (all pass).
Full suite clean.

## Safety / Contract Note

No new stable contracts promoted. All new surfaces are EXPERIMENTAL.
Live provider smoke never stores response content; requires explicit opt-in
env var; mock provider default unchanged for all other tests.
