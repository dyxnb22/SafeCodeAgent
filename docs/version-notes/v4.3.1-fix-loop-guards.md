# v4.3.1 — Fix Loop Guards

## Summary

v4.3.1 hardens experimental `sac fix --watch` with no-progress detection,
command timeout controls, and broader profile-suite reruns.

No stable contract changes. Patch proposals still require explicit `sac apply`;
`sac fix --watch` never auto-applies.

## Tasks

### T-4.3.1-A no-progress-stop

- `sac fix --watch` stops when the current failing redacted tail hash matches
  the previous failing fix iteration for the task.
- The task sidecar records experimental `failure_category: loop_no_progress`.
- CLI JSON includes `failure_category: loop_no_progress`.
- The human output suggests `sac status` and manual inspection.
- No follow-up patch is proposed when no progress is detected.

### T-4.3.1-B fix-timeout-and-broader-tests

- Added `sac fix --timeout-seconds N`.
- Default timeout remains 120 seconds.
- Timeout exits 124, records experimental `failure_category: command_timeout`,
  and does not propose a patch.
- Added `--rerun-suite test|all`.
- `test` uses the existing command selection precedence:
  `--test-command` > profile test > detector.
- `all` runs profile suites in deterministic order:
  `test`, `lint`, `typecheck`, `build`.
- Every `all` suite command goes through `ShellRunner` and command policy.
- Missing profile suites are skipped with a clear JSON note.
- Blocked suite commands stop safely with
  `failure_category: blocked_suite_command`.
