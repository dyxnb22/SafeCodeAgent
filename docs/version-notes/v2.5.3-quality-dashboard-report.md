# v2.5.3 — Quality Dashboard Report

## Summary

Adds a local-only eval report/dashboard generator that renders `TaskReplayRunner` / `ReplayResult` outputs into Markdown and HTML.  No external dependencies introduced.

## New Module

`src/safecode/report/dashboard.py` — stable rendering API for replay/eval report output.

### Public API

- **`ReportSummary`** (frozen dataclass): aggregated statistics — `total`, `passed`, `failed`, `pass_rate` (float in [0.0, 1.0]), `category_counts` (`dict[str, int]` keyed by `FailureCategory` value, in enum declaration order).
- **`build_summary(results)`**: constructs a `ReportSummary` from a sequence of `ReplayResult` objects.  Category counts follow `FailureCategory` enum order for determinism.  `pass_rate == 1.0` when `total == 0` (vacuously passing).
- **`DashboardRenderer`**: stateless renderer with two methods:
  - `render_markdown(results, title="Eval Report") -> str`
  - `render_html(results, title="Eval Report") -> str`

### Markdown report sections

1. **Summary** — total/passed/failed counts and pass rate.
2. **Failure Categories** (omitted when empty) — table of `FailureCategory` values and counts.
3. **Fixture Results** — one row per fixture: name, PASS/FAIL, network intent, audit events status, failure reasons.
4. **Failure Details** (omitted when all passing) — per-failed-fixture subsections with error, failure reasons, forbidden commands/file-writes violated, classified failures table (category, reason, detail).

### HTML report sections

Mirrors the Markdown structure with semantic HTML.  All user-supplied strings are escaped with `html.escape()`.  Status cells carry `.pass` / `.fail` CSS classes.

### Design decisions

- Output is **deterministic** and **snapshot-friendly**: same inputs → byte-identical output.
- **No external dependencies**: uses only `collections.Counter` and stdlib `html` module.
- **Backward-compatible**: `ReplayResult.classified_failures` defaults to `[]` (introduced in v2.5.2), so all existing `ReplayResult` call sites work unchanged.
- `build_summary` never raises on malformed or empty input.

- `src/safecode/report/dashboard.py` — new implementation.

## Test Coverage

112 tests in `tests/test_report_dashboard.py` covering:
- `build_summary`: empty results, all-passing, all-failing, mixed, category ordering and determinism.
- Markdown rendering: empty, passing-only, failed, forbidden violations, error results, multiple fixtures, pipe escaping in table cells, determinism.
- HTML rendering: empty, passing-only, failed, HTML escaping (tags, ampersands), forbidden violations, classified failure table, determinism.
- Failure category aggregation: multiple classified failures per result, aggregated across results, all 11 categories recognized.
- Backward compatibility: `ReplayResult` without `classified_failures` field, renderer and summary accept results with default field.
