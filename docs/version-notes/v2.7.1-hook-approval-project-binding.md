# v2.7.1 hook-approval-project-binding

Fixes audit Finding G: hook approvals must not carry across different project roots.

## Changes

- **`HookApprovalStore.config_hash()` now includes project root**: The project root is hashed
  and included in the `config_hash` payload. An approval granted in `/home/user/project-a` is
  now distinct from an approval in `/home/user/project-b`, even if the user, command, hook name,
  and hook config are identical.
- **Security review docs updated**: `docs/security/product-security-review-v2.6.md` now explicitly
  states that hook approvals are bound to the project root hash in addition to user, command,
  schema version, and config.
- **New test `test_approval_does_not_carry_across_projects`**: Verifies that a hook approval
  created under `project_a` is valid there but not valid under `project_b`.

## Acceptance

- `PYTHONPATH=src python3 -m pytest tests/test_security_hardening.py tests/test_tooling_security_evals.py -q` → 174 tests pass.
- `PYTHONPATH=src python3 -m pytest -q` → full suite passes.
