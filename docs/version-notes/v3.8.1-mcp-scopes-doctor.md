# v3.8.1 — MCP per-server scopes + mcp doctor

## Summary

- **T-3.8.1-A mcp-per-server-scopes**: Added `scope` field to `MCPServerConfig` with vocabulary `denied` / `read_only` / `write_proposal_required`. Parsed from `.sac/mcp.toml`; invalid values default to `denied` (fail-closed). Scope gate enforced in `MCPReadOnlyRunner.call_readonly` and `propose_write` **before** classification. Unknown server (not in config) defaults to `denied`. Known server without explicit `scope` defaults to `read_only`. A `read_only`-scoped server blocks write proposals. A `write_proposal_required`-scoped server allows write proposals through the existing approval flow.

- **T-3.8.1-B mcp-doctor**: Added `sac mcp doctor [server]` command (labeled `[EXPERIMENTAL]`). Reports binary path, scope, stdio configured, last call status from audit log, and lifecycle PID. Supports `--json`. Pure read — never spawns subprocesses or launches processes.

## Key invariants

- Scope gate always runs BEFORE classification in both `call_readonly` and `propose_write`.
- Unknown server scope defaults to `denied`; invalid TOML scope defaults to `denied`.
- `denied` scope blocks all call types before classification is even attempted.
- `read_only` scope blocks write proposals.
- `write_proposal_required` scope allows write proposals through approval gate.
- MCP write execution remains proposal/approval gated.
- No safety gate weakened; default LLM provider remains `mock`; no real network in tests.
