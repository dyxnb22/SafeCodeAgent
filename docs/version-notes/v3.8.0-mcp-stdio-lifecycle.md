# v3.8.0 — MCP stdio wire + lifecycle

## Summary

- **T-3.8.0-A mcp-stdio-wire**: Wired `StdioReadOnlyAdapter` into `MCPReadOnlyRunner.call_readonly` behind an explicit opt-in flag (`SAFECODE_MCP_STDIO_RUNNER=1` env var or `stdio_runner=True` constructor param). The static classification gate runs before any stdio call. Server-supplied classification fields in transport responses continue to be ignored. When the flag is off the behaviour is byte-identical to v3.7.3.

- **T-3.8.0-B mcp-lifecycle**: Added `src/safecode/mcp/lifecycle.py` with `MCPLifecycleManager` (start / stop / restart) and `MCPLifecycleResult`. Added `sac mcp start <server>`, `sac mcp stop <server>`, `sac mcp restart <server>` CLI commands (all labeled [EXPERIMENTAL]). PID files are tracked under `.sac/mcp/<server>.pid`. Each transition emits a `RuntimeLogger` event and an `AuditEvent`. `stop()` is idempotent and never raises on missing or dead processes.

## Key invariants

- Classification gate always runs BEFORE any stdio call.
- Server-supplied `"classification"` fields in JSON-RPC responses are ignored.
- `SAFECODE_MCP_STDIO_RUNNER=0` (default) → existing subprocess-shim path unchanged.
- Lifecycle commands are labeled experimental; MCP write execution and lifecycle not promoted.
- No safety gate weakened; default LLM provider remains `mock`; no real network in tests.
