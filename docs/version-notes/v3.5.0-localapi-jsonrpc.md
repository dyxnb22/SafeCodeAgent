# v3.5.0 — LocalAPI JSON-RPC Bridge (experimental)

## Summary

Exposes `SafeCodeLocalAPI` over a stdio JSON-RPC 2.0 transport.
Reuses existing MCP transport concepts. Only `ask`, `report`, `edit`,
and `apply` are exposed. Writes remain gated by the existing
pending-patch safety machinery (checkpoint + audit).

## New files

- `src/safecode/api/__init__.py` — package init.
- `src/safecode/api/jsonrpc.py` — stdio JSON-RPC 2.0 server:
  `process_request(line, project_root)`, `run_server(project_root, *, stdin, stdout)`,
  `CONTRACT_VERSION="1"`, `_SUPPORTED_METHODS`.
- `src/safecode/cli_api.py` — `api_app` Typer sub-app with `sac api jsonrpc`.
- `tests/test_ide_bridge_jsonrpc.py` — 64 new tests.

## Changes

- `src/safecode/cli.py`: registers `api_app` at `name="api"` (hidden).

## Invariants

- `process_request` never raises; all errors return JSON-RPC error responses.
- Error text never contains caller-supplied params content.
- `edit` calls `orchestrator.edit()` (creates `pending_patch.json`, no file writes).
- `apply` calls `orchestrator.preview_apply()` + `orchestrator.apply()` with
  full checkpoint and audit chain active.
- Transport is stdio newline-delimited JSON; designed for subprocess use by IDEs.
- `_SUPPORTED_METHODS` is a frozen set; no undocumented methods are dispatched.
- `CONTRACT_VERSION="1"` exported for manifest consumers.

## Experimental label

This surface is EXPERIMENTAL and is not a stable public contract.
