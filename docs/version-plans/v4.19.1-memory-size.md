## Why
Users currently have no SafeCode-managed way to ask "how much have I
accumulated under `.sac/`?". `du` works but is shell-specific and does not
break down by scope. `sac memory size` provides a deterministic
SafeCode-internal scope breakdown using only `Path.stat()` calls — no
contents read, no mutation, no shell out.

This is the second step of the v4.19.x observability train. It is the
counterpart to `sac task stats`: where the former summarizes one task,
this one summarizes the whole `.sac/` tree.

## Goals
- [ ] G1: Ship experimental read-only `sac memory size [--json]`.
- [ ] G2: Return a deterministic byte/file breakdown by named scope.
- [ ] G3: Touch only `Path.stat()`; never open file contents; never mutate.

## Requirements
- [ ] R1: Subcommand registered on `memory_app` as `size` (alongside `show`,
  `pin`, `unpin`, `add-note`, `clear`).
- [ ] R2: When `.sac/` does not exist, exit 0 with
  `{"exists": false, "total_bytes": 0, "total_files": 0, "scopes": [], ...}`
  and a friendly human message: `No .sac/ directory found.`
- [ ] R3: When `.sac/` exists, return:
  - `root`: absolute string path of `.sac/` (no redaction; this is a local
    filesystem path).
  - `exists`: `true`.
  - `total_bytes`: sum of `Path.stat().st_size` for every regular file under
    `.sac/` (symlinks skipped, hidden temp files matching
    `re.compile(r"^\..+\.[0-9a-f]{32}\.tmp$")` skipped to match the
    `_atomic_write` pattern used in `task/store.py`, `task/budget.py`,
    and elsewhere).
  - `total_files`: count using the same filter.
  - `scopes`: array of `{"name", "path_suffix", "bytes", "files"}` sorted by
    `name`. Default scopes are:
    - `audit` → `.sac/audit/`
    - `checkpoints` → `.sac/checkpoints/`
    - `memory` → `.sac/memory/`
    - `runtime_logs` → `.sac/logs/`
    - `tasks` → `.sac/tasks/` (whole subtree, includes `budgets/`)
    - `other` → anything under `.sac/` not captured by the above
  - `experimental`: `true`.
- [ ] R4: JSON output uses `CLIJSONResponse` under `command="memory size"`.
- [ ] R5: Human output is a Rich `Table` titled
  `[EXPERIMENTAL] .sac/ Size Breakdown` with columns Scope/Bytes/Files plus
  a "Total" footer row.
- [ ] R6: The walk uses `Path.iterdir()` recursion (not `os.walk`) and skips
  unreadable directories silently instead of raising.

## Implementation Notes
- New helper module:
  - `src/safecode/memory/sizing.py` — pure functions
    `compute_sac_size(root: Path) -> SacSizeReport` returning a Pydantic
    model with the fields in R3. No CLI dependencies.
- CLI:
  - `src/safecode/cli_memory.py` — add `@memory_app.command("size")` that
    calls the helper and prints either JSON or the Rich table.
- Test module:
  - `tests/test_memory_size.py` — cases:
    1. `.sac/` missing → `exists: false`, totals 0, no scopes.
    2. `.sac/` empty dir → `exists: true`, totals 0, all named scopes
      report 0/0.
    3. Single file under `.sac/memory/project.md` → totals match
      `len(content_bytes)`; only `memory` scope nonzero.
    4. Mixed scopes (`memory`, `tasks/<id>.json`, `audit/log.jsonl`) →
      per-scope counts add to totals.
    5. File outside named scopes (`.sac/extra/foo.bin`) lands in `other`.
    6. Symlink under `.sac/` is skipped.
    7. Temp file matching `r"^\..+\.[0-9a-f]{32}\.tmp$"` (sibling of an
      atomic write) is skipped.
    8. `tasks/budgets/<id>.json` is counted under `tasks` (not split out).
- Determinism:
  - Scopes returned in sorted order by `name`.
  - The helper is pure: no global state, no time, no randomness.
