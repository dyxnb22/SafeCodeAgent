# v7.0.x Agent Productization Follow-up

**Baseline:** v7.0.0 stable contract cut complete.
**Purpose:** Close the most visible gap between SafeCode Agent and opencode-style
daily agent use without weakening SafeCode's safety/audit moat.

metadata/narrative sync, single-command happy path, productized subagent roles,
and shell/session experience polish.

This is intentionally a v7.0.x patch/minor train, not a new major contract cut.
Stable contracts remain unchanged unless a future v8 candidate assessment says
otherwise.

## v7.0.2 — Single-command Agent Happy Path

### Problem

SafeCode has the pieces for agentic work, but the user-facing path still feels
like several internal surfaces stitched together. opencode-style daily use
expects a single command that shows: what the agent is doing, what it changed,
what validation ran, and where it stopped.

### Proposed User Flow

```bash
sac agent run "fix parser None handling" --full-auto --tests
```

Expected human output:

```text
Goal: fix parser None handling
Plan: 3 steps
Tools: search_symbol -> read_file -> edit_file -> run_command
Changed: src/parser.py, tests/test_parser.py
Validation: pytest -q tests/test_parser.py PASS
Status: completed
Rollback: sac rollback --session <id>
```

Expected JSON output keeps the existing `CLIJSONResponse` envelope and adds a
command-specific payload, not a new stable contract.

### Work Items

| ID | Task | Notes |
|---|---|---|
| V7.0.2-A | Add `--tests` option to `sac agent run` | Runs profile test suite or detected pytest command after apply-kind steps. |
| V7.0.2-B | Add compact run summary renderer | Summarize plan steps, tool calls, touched files, validation, approval stops, rollback command. |
| V7.0.2-C | Improve JSON payload | Include `session_id`, `stopped_reason`, `steps_count`, `tools_used`, `files_changed`, `validation`. |
| V7.0.2-D | Preserve safety pauses | GATE-tier commands still stop; high-risk commands still block; rollback command always shown. |
| V7.0.2-E | Add demo fixture | One deterministic mock project verifies the whole happy path. |

### Acceptance

```bash
uv run pytest tests/test_cli_agent_run.py tests/test_full_auto_mode.py tests/test_validation_loop.py -q
uv run sac agent run "fix add()" --full-auto --tests --json
```

### Non-goals

- Do not make `--full-auto` persistent.
- Do not auto-commit.
- Do not push or create PRs.
- Do not weaken approval tiers.

## v7.0.3 — Productized Subagent Roles

### Problem

SafeCode has subagent infrastructure, but it is not yet a product-level mental
model. opencode exposes clear role concepts. SafeCode should keep deterministic
audit/merge boundaries while making read-only assistance easier to invoke.

### Built-in Roles

| Role | Purpose | Default permissions | Typical use |
|---|---|---|---|
| `explore` | Map relevant files, symbols, tests, and risks before editing | read-only | "Where should I change this?" |
| `review` | Inspect pending diff for bugs, safety risks, missing tests | read-only | Before `sac apply` or commit |
| `scout` | Search broad codebase context and summarize candidates | read-only | Large repo localization |

### Work Items

| ID | Task | Notes |
|---|---|---|
| V7.0.3-A | Add role preset model | `SubagentRole` with name, prompt, allowed tools, max files, output schema. |
| V7.0.3-B | Add CLI entrypoints | `sac subagent explore`, `sac subagent review`, `sac subagent scout`. |
| V7.0.3-C | Journal role outputs | Record role, files inspected, findings, risks, confidence. |
| V7.0.3-D | Merge into agent context | Main loop can consume role summaries without copying raw noisy output. |
| V7.0.3-E | Docs and examples | README/MVP guide show when to use each role. |

### Acceptance

```bash
uv run pytest tests/test_subagent_pool.py tests/test_subagent_synthesis.py tests/test_subagent_activation.py -q
uv run sac subagent explore "find parser config handling"
uv run sac subagent review --pending
```

### Non-goals

- No DAG-style concurrent planning graph.
- No write-capable subagent by default.
- No hidden mutation through role prompts.

## v7.0.4 — Session and Shell Experience Polish

### Problem

SafeCode's shell/session functionality is powerful but still reads like a set
of engineering primitives. The gap to opencode is most visible in session
navigation: what happened, what changed, what tools ran, and how to resume.

### Target UX

Inside `sac shell`:

```text
/timeline        # chronological plan/tool/diff/test events
/sessions        # recent sessions with status and last goal
/status          # compact current session state
/tools           # stable + experimental tool list with approval flags
/resume <id>     # resume selected session
```

Outside shell:

```bash
sac session list
sac session show <id> --timeline
sac session resume <id>
```

### Work Items

| ID | Task | Notes |
|---|---|---|
| V7.0.4-A | Timeline projection | Convert journal events into compact `SessionTimelineEvent` rows. |
| V7.0.4-B | Shell commands | Add or polish `/timeline`, `/sessions`, `/resume`, `/status`. |
| V7.0.4-C | CLI session views | Add `sac session show --timeline` and improve `session list` scanability. |
| V7.0.4-D | Diff/test status in timeline | Show changed files, pending patch id, validation result, rollback hint. |
| V7.0.4-E | Human-output smoke tests | Snapshot-free tests for key labels and no-overlap/no-traceback behavior. |

### Acceptance

```bash
uv run pytest tests/test_cli_shell.py tests/test_cli_session.py tests/test_agent_journal.py tests/test_shell_session_quality.py -q
```

### Non-goals

- No IDE or desktop UI.
- No web UI.
- No stable machine-readable timeline contract in v7.0.x.

| Item | Reason |

| IDE plugin / desktop UI | Still outside the terminal-only product boundary. |
