# v6.24–v6.28 opencode Alignment Roadmap

Status: active  
Baseline: v6.23  
Scope: terminal-only; no IDE/desktop/cloud/plugin targets

---

## Background: Capability Gap Analysis (June 2026)

SafeCode v6.23 covers most of the opencode terminal feature surface:
conversation REPL, plan/build modes, multi-language LSP, approval tiers,
git-aware context, repair loop, session management, formatter integration,
and user tool config.

Five meaningful gaps remain for the terminal experience:

| # | Gap | Impact |
|---|-----|--------|
| 1 | Context compression is string-based truncation, not LLM summary | Long sessions lose facts; model "forgets" goals after 15+ turns |
| 2 | No global symbol search tool | Multi-file refactor requires repeated grep guessing |
| 3 | Native write tools still gate through pending-patch in full_auto | Agentic multi-file edits feel interrupted |
| 4 | Streaming diff output is plain text, not Rich-rendered | Diffs are hard to scan; tool looks unpolished |
| 5 | No AI-generated commit message | User must write commit messages manually after agent edits |

SafeCode keeps its unique advantages (checkpoint/rollback/audit chain,
dirty-tree guard, gate-tier safety) throughout all five versions.

## v6.24 — LLM-backed conversation compaction

### Problem
When `ConversationBuffer._compress_oldest_turns()` fires, it replaces the
old block with a literal text dump prefixed with a static banner. The model
receives low-quality "summaries" that miss goals, file paths, and failed
approaches, causing context drift after 15+ turns.

### Solution
Add `compact_with_llm(llm_client)` to `ConversationBuffer`. When an LLM
client is available and the buffer hits the compaction threshold, call the
LLM with the old block and ask for a structured summary:
- goals and constraints established
- files read or modified
- decisions made and approaches rejected
- open questions

Fall back to the existing string-based compress on LLM failure.

Wire `AgentLoop` to pass its LLM client to `_get_compactor()`.

### Acceptance
- 25-turn shell session: turns 1-10 compacted; turn 15 can correctly
  reference the goal from turn 3 because the LLM summary preserved it.
- LLM failure → string-based fallback, no crash.
- Secret-bearing content redacted before LLM call.

## v6.25 — Global symbol search tool (`search_symbol`)

### Problem
`find_references` is Python-only and requires Jedi. `grep_files` requires
the caller to know which regex to write. Neither gives the model a fast
"find where X is defined" entry point across languages.

### Solution
Add `search_symbol(name, kind=None, file=None)` native tool:

1. Try ripgrep (`rg --json`) if available — fastest, multi-language.
2. Fallback: `grep -rn` with a regex covering common definition patterns.
3. For Python files in results: run a quick AST pass to label each hit
   as `function`, `class`, `import`, or `variable`.

Return: list of `{file, line, kind, snippet}` capped at 50 results.
Register alongside `grep_files` / `search_files` in `read_tools.py`.

### Acceptance
- `search_symbol("parse_config")` finds the definition across .py, .ts, .go.
- `search_symbol("Config", kind="class")` narrows to class definitions.
- No ripgrep → grep fallback, results still returned.
- Path traversal blocked; .sac/ and .git/ excluded.

## v6.26 — Atomic multi-file writes in full_auto mode

### Problem
In `full_auto` mode the model calls `edit_file` / `write_file` native tools
one at a time. Each write goes through the pending-patch gate, so a 3-file
edit generates 3 sequential stop-for-approval interruptions even when the
user set `--full-auto`.

### Solution
When `full_auto=True` and the approval tier for the proposed edit is `auto`
or `confirm` (not `gate`), apply write-tool edits immediately in the same
turn without generating a pending-patch intermediate file:

1. `write_tools.py`: when `approved=True` AND `full_auto=True` on the
   context, apply the edit inline (checkpoint + audit still happen).
2. `MultiToolTurnRunner`: collect all write results from one turn and
   report them as a single observation block.
3. Checkpoint one combined entry per turn, not one per file.

Gate-tier edits (delete, shell, network, .env) still stop for approval.

### Acceptance
- `sac shell --full-auto`: model edits 3 files in one turn, no
  stop-for-approval between them.
- `/undo` rolls back the entire turn's edits atomically.
- Gate-tier operations still produce a confirmation prompt.

## v6.27 — Rich streaming diff rendering

### Problem
When a patch is proposed or applied, the diff is printed as raw unified-diff
text with no syntax colouring, no file-boundary panels, and no streaming
animation. It looks like plain debug output rather than a polished tool.

### Solution
Add `render_rich_diff(diff_text, *, title="", console=None)` utility in
`src/safecode/cli_diff_render.py`:

- Split diff into per-file hunks.
- Each file gets a Rich `Panel` with a coloured header (filename + ±lines).
- Hunk content rendered with `Syntax("diff", theme="monokai")`.
- `+` lines in green, `-` lines in red (via a custom Rich Highlighter).

Use in:
- `sac shell` when a write tool result shows a diff.
- `sac edit` / `sac apply` pending-patch display.
- `--stream` path: render chunks as they arrive.

### Acceptance
- `sac edit "..."` diff preview shows coloured panels per file.
- Non-TTY falls back to plain unified diff.
- Empty diff or non-diff text renders gracefully.

## v6.28 — AI-generated commit message (`sac commit --ai`)

### Problem
After an agent session the user must write a commit message manually.
The agent already knows what changed (checkpoint metadata, applied patch
content, task goal) — it should draft the message.

### Solution
Extend `sac commit` with `--ai` flag:

1. Collect: `git diff HEAD` (staged) or checkpoint file list + diffs.
2. Build a compact prompt: task goal + list of changed files + diff summary
   (capped at 4 KB to avoid token bloat).
3. Call LLM to generate a conventional-commit message
   (`type(scope): subject\n\nbody`).
4. Print the generated message, ask for confirmation (or `--yes` to skip).
5. On confirm: run existing `commit()` helper with the generated message.
6. `--dry-run`: print message and exit without committing.

Safety: diff content is redacted before LLM call; URL/key patterns stripped.

### Acceptance
- `sac commit --ai` after a bugfix: generated message is `fix(parser): ...`.
- `--dry-run` prints message, does not commit.
- LLM failure → clear error, user prompted to use `--message` instead.
- Diff content never leaks to error text.

## Non-goals for this train

- No IDE, desktop, or cloud agent features.
- No multi-user session sharing.
- No auto-push or remote CD.
- No removal of checkpoint/rollback/audit chain.
