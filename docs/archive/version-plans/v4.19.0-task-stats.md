## Why
Today the only way to inspect a task's accumulated history is `sac task show`,
which dumps the raw sidecar with no summary. Users following a long fix/edit
loop cannot quickly see "how many iterations, what failed, was budget tripped"
without reading every iteration record. `sac task stats` answers that question
in one read-only command, with stable JSON suitable for scripting.

This version is the first step in the v4.19.x observability train. It does not
introduce any mutating behaviour, network call, or policy change.

## Goals
- [ ] G1: Ship experimental read-only `sac task stats [--task <id>] [--json]`.
- [ ] G2: Surface a deterministic redacted summary built from existing
  `TaskState`, `TaskBudget`, and `MemoryFacade` data.
- [ ] G3: Mutate nothing under `.sac/` and call no model, network, or shell.

## Requirements
- [ ] R1: When `--task` is omitted, fall back to `TaskStore.current_id()`.
- [ ] R2: When no `--task` and CURRENT is unset, exit 1 with the standard
  message `No task specified and no CURRENT task.` (matches `sac task show`).
- [ ] R3: When the resolved task id has no sidecar, exit 1 with
  `Task not found: <id>` (matches `sac task show`).
- [ ] R4: When the resolved task sidecar exists but `--task` was explicit and
  the task is `closed`, still succeed (we are reading, not mutating).
- [ ] R5: Output histograms are computed with deterministic sorted keys:
  - `iterations.by_event` — histogram of `TaskIteration.event`.
  - `iterations.by_status` — histogram of `TaskIteration.status`,
    skipping entries where `status is None`.
  - `iterations.by_failure_category` — histogram of
    `TaskIteration.failure_category`, skipping `None`.
- [ ] R6: Output includes:
  - `task_id`, `status`, `created_at`, `updated_at`.
  - `goal` (redacted via `redact_secrets`).
  - `iterations.total: int` and `iterations.last_iteration_index: int` (`-1`
    when empty).
  - `iterations.last_event: str | None` (most recent iteration's `event`).
  - `pending_patch_id: str | None`.
  - `last_command: {"command": str, "exit_code": int | None}` (redacted) or
    `None` when unset.
  - `audit_trace_count: int`.
  - `budget: {steps, time_seconds, retries, tokens}` from
    `TaskBudgetStore.load(task_id)` (defaults when no sidecar).
  - `pinned_files.count: int` from `MemoryFacade.read_pinned_files()`.
  - `experimental: true`.
- [ ] R7: JSON output uses `CLIJSONResponse` envelope under
  `command="task stats"`.
- [ ] R8: Human output renders as a Rich-styled `[EXPERIMENTAL] Task Stats`
  block listing the same fields without emojis.

## Implementation Notes
- Main file:
  - `src/safecode/cli_task.py` — add `@task_app.command("stats")` and a small
    private helper `_histogram()` that ignores `None` and sorts keys.
- Test module:
  - `tests/test_task_stats.py` — at least the following cases:
    1. Missing CURRENT → exit 1, error message matches R2.
    2. Explicit `--task <missing>` → exit 1, error message matches R3.
    3. Brand-new task (zero iterations) → totals are 0, histograms `{}`,
      `last_iteration_index == -1`, budget defaults applied.
    4. Task with mixed-event iterations → `by_event` and `by_status` reflect
      counts; `None` statuses skipped.
    5. Task with a `failure_category` in some iterations only → `None` entries
      skipped from histogram.
    6. `last_command` redacts a sample value containing `api_key=secret`.
    7. Goal containing `API_KEY=abc` is redacted in both JSON and human output.
    8. JSON envelope uses `command="task stats"` and `status="success"`.
    9. `pinned_files.count` reflects `MemoryFacade.pin_file()` insertions.
    10. `audit_trace_count` matches `len(state.audit_trace_ids)`.
    11. `budget` reflects values stored via `TaskBudgetStore.save()`.
    12. Closed task (status=`closed`) is readable and reports `status:
      "closed"`.
- Determinism:
  - `_histogram()` sorts keys with the default lexicographic order.
  - Output dict keys are stable across runs (no `set()` round-trips).
