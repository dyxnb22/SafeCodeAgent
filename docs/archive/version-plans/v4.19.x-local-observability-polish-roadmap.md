# v4.19.x: Local Observability Polish Roadmap

## Status
Planned. Active forward plan on the `dev/v4.19` branch.

- Baseline context: `.claude/skills/current/SKILL.md`

  `scripts/new-version-plan.sh`).

## Train Theme

The v4.14–v4.16 train delivered usability. The v4.17–v4.18 train delivered shell
and interaction polish. v4.19.x is a small, focused **local observability**
train: it surfaces what already lives under `.sac/` without changing any
mutating behavior, policy gate, or stable contract.

Every command introduced in this train is:

- **Read-only.** No mutation of task sidecars, audit log, checkpoints, pending
  patches, or memory.
- **Deterministic.** No model calls, no network, no shell execution against
  project tooling.
- **JSON-friendly.** Uses the existing `CLIJSONResponse` envelope (stable
  contract 11).
- **EXPERIMENTAL.** No new stable contract promoted in any v4.19.x release.

## Non-Goals (Explicit Deferrals)

These remain explicitly deferred and are NOT part of v4.19.x:

- RAG / embeddings / vector storage.
- LangGraph or any background scheduling.
- Remote push / PR creation.
- IDE / TUI surface expansion.
- Hooks/automation expansion.
- Auto-apply, auto-commit, auto-push.

## Versions

### v4.19.0 — `sac task stats`

A read-only per-task observability command. Today, `sac task show` displays the
sidecar's raw fields but does not summarize iterations or failure categories.
`sac task stats` returns a deterministic redacted summary.

**Surface:**

```
sac task stats [--task <task_id>] [--json]
```

When `--task` is omitted it resolves CURRENT and errors with the standard
"No task specified and no CURRENT task." message when CURRENT is unset
(matching `sac task show`).

**Returned fields:**

- `task_id`, `status`, `created_at`, `updated_at`, `goal` (redacted).
- `iterations.total`: integer iteration count.
- `iterations.by_event`: deterministic histogram of `event` field
  (sorted keys, integer counts).
- `iterations.by_status`: deterministic histogram of `status` field
  (skips entries with `status=None`).
- `iterations.by_failure_category`: deterministic histogram of
  `failure_category` (skips `None`).
- `iterations.last_event`: most recent iteration's `event` (or `None`).
- `iterations.last_iteration_index`: integer (-1 if empty).
- `pending_patch_id`: pass-through from sidecar.
- `last_command`: redacted command string + `exit_code` (or `None`).
- `audit_trace_count`: integer length of `audit_trace_ids`.
- `budget`: `{steps, time_seconds, retries, tokens}` from
  `TaskBudgetStore.load(task_id)` (defaults if no sidecar exists).
- `pinned_files.count`: integer count of MemoryFacade pinned files.
- `experimental`: `true`.

**Out of scope for v4.19.0:**

- No token-spend computation. Per-task tokens are only the budget value,
  not consumption — consumption tracking is not part of this train.
- No iteration time histogram. The sidecar does not currently store wall
  duration per iteration.
- No mutation of any sidecar field.

**Acceptance commands:**

```
PYTHONPATH=src python3 -m pytest -q tests/test_task_stats.py
PYTHONPATH=src python3 -m pytest -q
uv run sac task stats --task <id> --json
uv run sac task stats --json
```

**Main files:**

- `src/safecode/cli_task.py` — add `@task_app.command("stats")`.
- `tests/test_task_stats.py` — new test module.
- `docs/version-notes/v4.19.0-task-stats.md` — version note.

### v4.19.1 — `sac memory size`

A read-only `.sac/` storage breakdown. Today there is no way to ask the agent
how much it has accumulated locally. `sac memory size` walks the `.sac/`
subtree and returns a deterministic byte/entry breakdown per scope.

**Surface:**

```
sac memory size [--json]
```

**Returned fields:**

- `root`: absolute path of `.sac/` (string, not redacted — local path only).
- `exists`: `true` if `.sac/` exists.
- `total_bytes`: aggregate file size in bytes (regular files only,
  symlinks skipped).
- `total_files`: aggregate file count.
- `scopes`: array of `{name, path_suffix, bytes, files}` entries, sorted by
  `name`. Default scopes:
  - `memory` → `.sac/memory/`
  - `tasks` → `.sac/tasks/` (entire subtree, including budgets)
  - `checkpoints` → `.sac/checkpoints/`
  - `audit` → `.sac/audit/`
  - `runtime_logs` → `.sac/logs/` (if present)
  - `other` → everything under `.sac/` not matched by the named scopes
- `experimental`: `true`.

**Determinism guarantees:**

- Sizes use `Path.stat().st_size` on regular files; symlinks are skipped.
- Hidden files are included; sibling temp files (`.<name>.<hex>.tmp`)
  created by atomic writers are skipped.
- Output is stable across runs given a stable filesystem.

**No mutation:**

- The command never creates `.sac/` if it does not exist (it reports
  `exists: false` and returns zero counts).
- The command never opens file contents.

**Acceptance commands:**

```
PYTHONPATH=src python3 -m pytest -q tests/test_memory_size.py
PYTHONPATH=src python3 -m pytest -q
uv run sac memory size --json
```

**Main files:**

- `src/safecode/cli_memory.py` — add `@memory_app.command("size")`.
- `src/safecode/memory/sizing.py` — pure helper for the walk.
- `tests/test_memory_size.py` — new test module.
- `docs/version-notes/v4.19.1-memory-size.md` — version note.

## Cross-Cutting Requirements

- Redact every user-visible string that originates in task goals,
  commands, or memory entries through the existing
  `safecode.context.redactor.redact_secrets` function.
- Reuse `CLIJSONResponse` and `render_json` for JSON output.
- Reuse `TaskStore.current_id()`, `TaskStore.load()`, and
  `TaskBudgetStore.load()` (do not duplicate sidecar parsing).
- Reuse `MemoryFacade.read_pinned_files()` rather than reading
  `.sac/memory/pinned-files.txt` directly.

## Backward Compatibility

- Adds two new EXPERIMENTAL subcommands. No existing command, flag,
  or output format changes.
- No stable contract is promoted; no migration is required.
- `.claude/skills/current/SKILL.md`, `.claude/versions.json`, and the
  final-status doc are updated only at end of train.

## Testing Strategy

Per-version targeted tests must pass:

- `tests/test_task_stats.py` (~10 cases)
- `tests/test_memory_size.py` (~8 cases)
- Extended `tests/test_mvp_docs.py` rows.

Cross-cutting regression: `PYTHONPATH=src python3 -m pytest -q` must remain
green across each release in the train.

## Risk Notes

- `sac memory size` walks `.sac/` and could touch many small files in
  long-running projects. Capping is not necessary because (a) `.sac/` already
  has bounded layouts (200-entry recent failures, 200 recent edits, sorted
  pinned files) and (b) the walk uses `Path.stat()` only, no contents read.
- `sac task stats` runs over `iterations` which is bounded by the existing
  step budget (default 8) per `AgentLoop.run()`.
